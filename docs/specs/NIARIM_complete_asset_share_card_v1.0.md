# NIARIM ブラシ・トーン・スタンプ 完全共有カード 正式仕様書

**仕様ID:** NIARIM-ASSET-CARD-001  
**版:** 1.0（確定方針・実装契約案）  
**作成日:** 2026-11-12  
**対象:** NIARIM `dev_branch` / Android（SP・DeX/PCモード共通）  
**対象素材:** ブラシ・トーン・スタンプ

## 1. 目的・決定事項

**利用者が素材一つを「画像1枚（PNG）」として書き出し、相手がNIARIMの該当タブの「読込」ボタンからそのPNGを選ぶだけで、名称・全設定・使用画像（複数枚含む）を復元できること。** 素材の見た目・名前・QRコードを同じ画像内に載せ、アプリを持たない人にも何の素材か分かるカードとする。

- **採用:** 完全共有カードPNGのみ。ブラシ・トーン・スタンプで同じUI・同じカード規格を使う。
- **不採用:** `.niabrush` / `.niatone` / `.niastamp` の新規書き出しUI、単体の軽量QR共有、QRテキスト貼付による素材の取り込み、クラウドURL必須方式、分割カード方式。
- **読込入口:** 各「ペン」パネルの「読込」。PNGを選択→プレビュー→検証→取り込み。取り込み先タブとカード種別が違えば切り替える案内を表示する。ファイルを選択しただけで登録しない。
- **共有入口:** 各素材行の三点メニュー→「共有カードを書き出す」。完成したPNGに対して端末の共有シートを開ける。専用アーカイブを利用者に別ファイルとして見せない。
- **端末内操作完結:** 書き出し・読み込み・検証はオフラインで動作。アカウント、外部サーバー、通信、外部ストレージの登録を必須にしない。

## 2. 重要な技術上の区別（正確な復元のため）

ブラシ・スタンプ・トーンの「見本の絵」と、実際に使う「元画像ファイル」は同一とは限らない。拡縮表示されたプレビューを再切り出しして元画像を再構築すると、透明度・ピクセル値・複数画像・描画パラメータを完全には戻せない。

したがって **1枚のPNGは二層構造** とする。

1. **目で見えるカードの画素:** 素材名、種別、QR、元画像のサムネイル（複数画像は枚数と縮小表示）、実際のストローク／トーン／スタンプ見本、NIARIM識別子、互換バージョンを表示する。
2. **同じPNG内部の機械可読ペイロード:** PNG拡張チャンクに圧縮済みの設定JSONと使用画像のオリジナルバイト列を格納する。画像の見た目から切り出してデータを復元しない。

QRは「このPNGがNIARIM共有カードである」「バージョン」「素材種別」「ペイロード照合用の短い識別情報」を表す**カード識別用**であり、単独では設定や画像を復元しない。ユーザーがQR単体を保存・共有する機能は設けない。

**制約:** SNSでJPEGに再圧縮された画像、スクリーンショット、画像編集アプリで再保存したPNGは内部ペイロードが失われる場合がある。見た目が同じでも完全な復元は保証できない。エラー時は「この画像には復元情報がありません。送信元の元のPNGをファイルとして共有してください」と明示。通常のSNS画像表示だけで常に復元できるという表現はしない。

## 3. カード画像の見た目

基本デザインは縦長の高解像度PNG（推奨 **1200×1600px**、カード自体は縮小プレビュー可能）。対象となる素材の元画像は設定に応じて複数。表示領域は固定比率とし、読み取り用チャンクの位置とは独立させる。

| 領域 | 画面表示 | 用途 |
|---|---|---|
| ヘッダー | NIARIM / ブラシ・トーン・スタンプ | 種別識別 |
| 名前 | 素材名（長い場合は折り返し） | 目視で識別 |
| 中央の大きな領域 | 1本の代表ストローク／代表パターン／代表スタンプ | 使い心地を判断 |
| 元画像一覧 | ペン先・パターン画像・スタンプ画像のサムネイル、全枚数 | 画像を持つ素材の構成が分かる |
| QR | 白余白付きの高コントラストQR | カード照合・案内（単独の読み込み機能ではない） |
| フッター | `NIARIM SHARE CARD`、フォーマット版、識別ハッシュ短縮形 | 互換性・判別 |

表示例: 「木炭ブラシ」 / カーブのストローク見本 / 使用画像×3 / QR。元画像が存在しない数式・パラメータ生成素材の場合は「内蔵パターン（外部画像なし）」と表示し、描画を再現する設定値そのものを内部保存する。

## 4. ファイル構造・バージョン管理

- MIME: `image/png`、拡張子 `.png`。画像ファイル1枚のみ。
- カード形式識別子: `niarim.asset-card`、schemaVersion `1`、エンコーディング `UTF-8`。
- PNG内の**独自の補助チャンク**（規格に従うancillary/privateチャンク）にマニフェスト＋リソースを格納する。実装ではチャンクタイプ、CRC-32、サイズ上限、チャンク順序を明確に定義してから固定する。標準的なPNG表示アプリは追加チャンクを無視して表示できること。
- マニフェスト: `kind`(`brush|tone|stamp`)、`schemaVersion`、`displayName`、設定オブジェクト、画像エントリー（順序・ファイル形式・SHA-256・バイト長）、生成時のアプリ互換情報、全体の整合性ダイジェスト。
- 設定: `Brush.toJson()` / `Tone.toJson()` / `Stamp.toJson()` で再現に必要な値を欠落なく保存。端末固有ID・フォルダID・ローカル絶対パスは新端末で再割当て。タグ／不透明度／筆圧／散布／カスタムパラメータ／内蔵パターン識別子／画像選択順を維持。
- 元画像: 画像ファイルを**バイト列そのまま**格納。複数枚は順序を維持。アルファと透過色・画像寸法を保持。サムネイルだけをペイロード代用しない。
- 整合性: 各画像SHA-256とマニフェストのSHA-256を検証。PNG外観だけ一致していても内部検証に失敗すれば登録を中止。
- 将来の互換性: 未知の`schemaVersion`は無断で読み込まず、更新案内と安全なエラーを出す。フィールドの追加は後方互換性ルールに従う。

## 5. 書き出しフロー

1. ペン→「ブラシ／トーン／スタンプ」タブ→対象行の「…」→ **「共有カードを書き出す」**。
2. 対象素材の設定と関連するすべての使用画像を収集。見つからない画像・読めない画像があれば処理を中断し、部分カードを成功扱いしない。
3. プレビュー・素材名・サムネイル・QRを描画してPNG生成。完全復元データを同じPNG内部に埋め込む。
4. 生成PNG自身をデコーダーで読み戻し、全項目・全画像の一致を自動検証してから保存を確定。
5. 完了ダイアログにカードプレビュー、**「保存」**と**「共有」**を表示。端末の共有機能でPNG一枚を送信する。
6. 生成中・失敗時はスピナーと原因。連打による二重作成・二重共有を防止する。

**内蔵素材**も複製・編集なしでそのままカード化可能。送信者が素材の作者であると誤認させる著作者表示は強制しない。ファイル名はサニタイズした素材名＋`.png`、同名衝突時は安全な連番。

## 6. 読み込みフロー

1. ペン→該当タブ→ **「読込」**。ファイル選択はPNGのみ。カメラでQRコードのみを読ませる入口・テキスト貼付入口・専用ファイル入口は設けない。
2. PNGシグネチャ・チャンクCRC・サイズ上限・マニフェスト・バージョン・SHA-256を検証。通常の写真や見た目だけのスクリーンショットは拒否する。
3. カード内の見本と素材名を表示し、**「ブラシとして追加」**など種別に合う操作を選んで確定する。
4. 画像をアプリの専用素材ディレクトリに一時展開。画像の正当性・設定の値域・参照数を確認してから原子的に登録する。
5. 元IDは新規IDに置換、フォルダIDは未指定、名前重複時は自動で区別（例: `木炭ブラシ (2)`）。タグは維持、お気に入りは受信側既定OFF。既存データや組み込みプリセットは上書きしない。
6. 完了後、新しい素材の一覧へスクロールして選択可能にする。取り込み失敗時の一時画像・レコードはロールバックして残さない。

## 7. 制限・品質・セキュリティ

- 画像数と解凍後サイズの安全上限を設ける。初期推奨: 元画像**最大16枚**、各**4096×4096px**、元画像合計**32MiB**、カードPNG全体**40MiB**、マニフェスト**256KiB**。超過時は明示的に拒否し、端末メモリーを守る。ここでの値は初期実装の推奨上限であり、最終的に実機負荷試験で確定する。
- 圧縮データの展開は容量上限・画像寸法・処理タイムアウトを課す。任意パス・絶対パス・`../`を信用せず、ファイル名は新規生成する。悪意あるPNG、特大チャンク、壊れた画像、CRC破損、重複ID・衝突に耐える。
- 外部リンク・スクリプト・プログラムコードは実行しない。共有内容は**素材データだけ**。
- 透過・画素パターン・圧縮前の画像バイト・ブラシ設定の保存復元の同一性をテストする。元画像が使われていない内蔵素材は設定と生成パラメータが一致することを確認する。
- デザイン上の見本は共有のためのイメージであり、特殊な筆圧デバイス／描画環境による描画差を完全保証するものではない。

## 8. UI・文言（SP/PC/DeX共通）

| 場所 | 採用ラベル | 挙動 |
|---|---|---|
| 統合パネル | **ペン** | ブラシ・トーン・スタンプの3タブ |
| 各タブ上段 | フォルダ / 新規 / 読込 | 新規は画像から素材を作成、読込は共有カードPNG |
| 各素材行 | … > **共有カードを書き出す** | PNGカード生成、プレビューと保存／共有 |
| 読込完了確認 | **「◯◯として追加」** | 登録前確認 |
| 不正なPNG | **「NIARIMの共有カードではありません」** | 通常画像を誤登録しない |
| ペイロード消失 | **「復元情報がありません。元のPNGファイルを共有してください」** | SNS再圧縮を説明 |
| 互換性不足 | **「このカードは新しいバージョンで作成されています」** | 更新案内 |

既存の `.niabrush` / `.niatone` / `.niastamp` 書き出しやブラシ単体QR共有は、**新しい操作としてはUIから外す**。旧ローカルデータを無断削除しない。ユーザー向けに専用ファイル・軽量QRという第二の共有方式を残さない。

## 9. テスト・受け入れ条件

**A. 完全ラウンドトリップ** — ブラシ、トーン、スタンプの3種で、内蔵素材・画像1枚・複数画像のカードを作成→別の初期化済みサービスへ読み込み、元画像のバイト・順序・設定・タグが一致すること。

**B. 単一PNG** — 出力はカードPNG一枚で完結し、付随する`.nia*`ファイル、別のQRテキスト、通信・外部クラウド参照を要求しないこと。

**C. QR・見た目** — カードに素材名・種別・見本・画像サムネイル・識別QRが視認でき、QRだけでは復元不能であることを正しく案内すること。

**D. 実画面** — SP、PC/DeX双方で「読込」「…→共有カードを書き出す」「プレビュー」「取り込み完了」を撮影し、誤操作／オーバーフローがないこと。

**E. 破損耐性** — JPEG、通常PNG、ペイロード除去PNG、CRC異常、ハッシュ不一致、サイズ超過、未知バージョン、画像欠損は**失敗として明示**し、取り込み一覧に半端な素材を作らないこと。

**F. 同居データ保護** — 他の利用者データ、既存ブラシ・トーン・スタンプ・フォルダ、お気に入りが変更されないこと。

**G. 移行** — 従来のファイル書き出し／単体QRの操作を共有導線からなくし、公開UIにPNGカードのみ表示されること。

## 10. 実装単位と進捗判定

1. `shared_asset_card_codec.dart` — PNGチャンク格納・復号・検証（純Dart、単体テスト）。
2. `shared_asset_card_service.dart` — 3素材の設定と全元画像の収集／復元、元IDの安全な再割当て、失敗時ロールバック。
3. `shared_asset_card_view.dart` — 実画面カードのレンダリング、QRと見本表示、PNGとして描画・埋め込み。
4. ブラシ／トーン／スタンプ各パネル — 共通書き出しアクション、共通PNG読込・確認ダイアログ。古い共有UI除去。
5. `test/shared_asset_card_*` / `test/visual/...` — バイナリの完全往復、壊れたカード、画面、実機検証。

**完了の定義:** 上記A〜Gが実行結果と保存された実画面キャプチャで確認できた時だけ「完全共有カードの実装完了」と報告する。**本仕様書の作成自体は実装・検証完了を意味しない。**

## 11. 既存コードとの接続点

現行の `BrushService` / `ToneService` / `StampService` のモデルJSON・保存機構、`PenSubToolPanel`、既存の描画見本 `StrokeSamplePreview`、既存のQR描画ライブラリを活用できる。ただし現存する`QrShareDialog`の文字列転送と`.nia*` ZIPファイルの共有UIを、そのまま完全共有カードと呼ばない。完全カードは同一PNGの**見た目＋内部ペイロード**で成立する別規格である。

---

**決定済みのユーザー要件を優先:** 共有形式を増やして複雑にせず、ブラシ・トーン・スタンプをすべて同じ「1枚のPNGカード」「読込」導線に統一する。
