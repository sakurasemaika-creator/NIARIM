# 24\_テーマ・外観仕様

## 概要

NIARIMではUI全体の外観を自由に変更できる。変更はアプリ全体へ即時反映される。キャンバスデータには影響しない。無料版・プレミアム版共通で利用できる。

---

## カスタマイズ項目

| 項目             | 内容                                     |
| ---------------- | ---------------------------------------- |
| アクセントカラー | ボタン・選択枠・スライダーなどの強調色   |
| 本文・通常の文字色 | 本文、見出し、通常の項目名 |
| ボタン内の文字・アイコン色 | 塗りつぶしボタンと起動画面の大きな導線の前景色 |
| メニュー・上部バーの文字色 | メニュー項目、上部バーのタイトル・アイコン |
| 選択中の文字・アイコン色 | 選択色の上に表示する文字・アイコン |
| パネル背景色     | レイヤーパネル・ツールパネルなどの背景色 |
| メニュー背景色   | 三点メニュー・ポップアップの背景色       |
| 選択色           | 選択中項目のハイライト色                 |
| 更新マーク色     | ❗アイコンの色                           |

すべてカラーピッカー（HSV / RGB / HEX）で自由に設定できる。

本文を黒く、塗りつぶしボタン上の文字を白くする等の組み合わせを独立して指定できる。本文・ボタン・メニュー・選択中の4種類の前景色は**すべて必須設定値**であり、未設定・null・自動算出フォールバックは設けない。すべての組み込みプリセットも4つの色を明示的に持つ。色の設定と保存は自由で、読みにくさを理由に拒否・補正しない。未リリース段階なので旧形式との互換変換は設けず、不完全な旧形式データは新しい有効なプリセットとして扱わない。

「ボタン内の文字・アイコン色」は塗りつぶしボタン向け。枠線ボタン・テキストリンクなど、背景に塗りつぶしのない操作には従来のアクセント/本文の配色を使用する。 派生色の淡い`primaryContainer`・`secondaryContainer`上の文字は通常文字色を使い、ボタン専用の白文字を誤適用しない。プロジェクト一覧の複数選択チェック、およびチェックボックスの選択済み状態では、背景に「選択色」、チェック印に「選択中の文字・アイコン色」を使う。別の独立UI領域（カラーサークル、動画・アートワークなど）の固有色は変えない。

## ライト・ダーク判定

アプリのベーステーマは別の保存項目として持たず、各プリセットのパネル背景色から明暗（FlutterのBrightness）を決める。初期選択は「レッド（ライト）」。ダークに切り替えたい場合はダーク系のプリセットを使うか、背景色を編集する。これはFlutterの標準部品に必要な明暗モードの判定であり、ユーザーの文字色や背景色を自動補正する意味ではない。

## テーマプリセット

### 保存内容

1つのテーマプリセットには以下を保存する。

- アクセントカラー
- 本文・通常の文字色
- ボタン内の文字・アイコン色（必須）
- メニュー・上部バーの文字色（必須）
- 選択中の文字・アイコン色（必須）
- パネル背景色
- メニュー背景色
- 選択色
- 更新マーク色
- （将来追加されるUIカラー設定も含められるよう拡張可能）

### 操作

| 操作           | 内容                                              |
| -------------- | ------------------------------------------------- |
| 新規作成       | 現在の設定を新しいプリセットとして保存            |
| 上書き保存     | 既存プリセットを現在の設定で上書き                |
| 名前変更       | プリセット名を変更                                |
| 複製           | プリセットをコピーして追加                        |
| 削除           | プリセットを削除                                  |
| 並び替え       | ドラッグで順序変更                                |
| お気に入り登録 | よく使うプリセットをお気に入りに登録              |
| 読み込み       | .niathemeファイルを読み込んでプリセット一覧へ追加 |
| 共有           | .niathemeファイルとして書き出して共有             |
| 適用           | タップで即座に反映                                |

### 一覧表示

各プリセットに色設定から自動生成したサンプルUIイメージを表示する。名前だけでなく見た目で選べる。

### 初期プリセット

アプリの初期状態では **28種類**の組み込みプリセットを用意する。虹7色のライト/ダーク14種類に加え、パステル・ニュアンス・くすみカラーのライト/ダーク14種類を含む。既定選択はレッド（ライト）。

- レッド・オレンジ・イエロー・グリーン・ブルー・藍色・パープル（各ライト／ダーク）
- ピンク・ライトパープル・ライトブルー・エメラルドグリーン・くすみピンク・くすみブルー・くすみグリーン（各ライト／ダーク）

各プリセットがアクセント・本文文字・ボタン文字・メニュー文字・選択中文字・パネル背景・メニュー背景・選択色・更新マーク色をそれぞれ明示的に定義する。明るいアクセントのボタンは暗い文字、暗いアクセントのボタンは白文字など**プリセット作成時に選んだ配色**を保持する。ユーザー変更時には自動コントラスト補正しない。

## テーマの共有（初期実装）

テーマプリセットを `.niatheme` ファイルとして書き出し・読み込みができる。

```

↓
「テーマを書き出し」
↓

共有
```

```
.niatheme ファイルを受け取る
↓
プレビュー表示
↓
保存
↓

```

## UIテーマとワークスペースの区別

UIテーマとワークスペースは完全に独立した設定である。

| 設定           | 保存内容                                           |
| -------------- | -------------------------------------------------- |
| UIテーマ       | 配色・アイコン・外観のみ（ツール配置は保存しない） |
| ワークスペース | 表示ツール・早替えツール・パネル配置               |

テーマを変更してもワークスペースは変わらない。ワークスペースを変更してもテーマは変わらない。

## プレビュー

「テーマ・外観」のカラーチップの上に、**プロジェクト一覧画面を縮小したライブプレビューカード**を1枚置く。カード全体をタップした場合のみ、16画面のフルスクリーン専用プレビューを開く。カードは固定画像を使用せず、全画面ギャラリーと共通のFlutter描画部品を使う。選んだテーマ色の変更は設定画面の再描画時にカードにも反映される。カードの中身は操作できず、押したときだけギャラリーを開く。プレビューは左右スワイプで次の独立画面へ移動でき、画面下部の小さな操作バーに前後の矢印・画面番号・閉じるボタンを置く。操作バーを一時的に隠すこともできるため、画面全体を端末サイズのまま確認できる。

- 日常的に使う制作・作品広場の画面を中心にした**16枚の配色見本**を表示する。フォルダー移動、タブ切替、検索・並べ替え、開閉パネル、一般のポップアップを別の見本として数えない。全独立画面を網羅するギャラリーではない。
- 現行の対象は、起動画面、プロジェクト一覧、新規プロジェクト、プロジェクト詳細、キャンバス、タイムライン、作品書き出し、書き出し完了、セーブ管理、素材管理、作品広場、作品詳細、投稿、投稿者の作品、自分の投稿、フォロー通知の16件。共有・ゴミ箱・各種設定・Help/Tips・法務等の本番画面は存在するが、現在の配色見本からは除外する。
- 「書き出し完了」は本番UIではダイアログだが、利用者の明示指定により**完了状態の例外的な見本**として含める。一般のダイアログやパネルは追加しない。
- 見本はFlutterの標準UI部品と現在のテーマのThemeData/ColorSchemeを直接利用する。色を固定した画像ではなく、**現在選ばれているテーマの色**を反映する。 カラーチップの見本では`ColorScheme`の種色から派生した色で代用せず、`panelBgColor`・`menuBgColor`・`updateMarkColor`などユーザーの入力した**元の設定値**を表示する。起動画面のボタン文字およびロゴ内部は`buttonTextColor`を使用する。
- 端末幅いっぱいの画面内で、文字・アイコンは実物に近い論理ピクセルサイズを使い、ツールバー・フレーム一覧・画面領域の比率を近づける。すべてのページは制作物の**見本データ**であり、実画面そのもののスクリーンショットではない。実データや動画、SNSや端末ストレージへのアクセスはしない。
- 縮小カードは端末の論理画面サイズを維持した状態で1画面だけ構築し、FittedBoxで縦横を**同じ倍率で縮小**する。文字・アイコンの形やツールバーの縦横比を変更しない。別の16枚を起動したり、サムネイルのためにデータ取得したりしない。スマホの狭幅でも表示可能な寸法とし、横長端末では全体をさらに縮小してカードの幅を抑える。
- FlutterのPageView.builderで現在ページと必要な隣接ページだけを描画し、RepaintBoundaryで囲って無駄な再描画を減らす。画面遷移やスクロールを行っても作品・設定・ユーザーデータへ変更を加えない。
- このプレビューはテーマの見え方を事前確認する機能。すべての画面の最終的なピクセル単位の再現性や、ツールバー配置・データ内容・ネットワーク状態を保証するものではなく、完全な一致には実画面でのキャプチャ検証が必要。

## 色設定の自由度と、操作不能からの復旧

テーマ・外観は、ユーザーが自由に色を組み合わせられるようにする機能である。一般的に読みにくい組み合わせ、低コントラスト、色相差が小さい組み合わせもユーザーの選択として許容し、コントラスト比・配色美・アクセシビリティ基準だけを理由にテーマ色の保存を拒否しない。設定時にエラーを出したり、変更前の色へ巻き戻したりするのではなく、操作不能になりかねない現在のテーマから自力で復旧できる手段を提供する。

### 起動画面・「テーマ・外観」右上のリセットボタン

- 現在のテーマが、設定画面や起動画面の主要導線などを事実上操作不能にしかねない組み合わせと判定された場合、起動画面と「テーマ・外観」の両画面右上に共通のリセットボタンを表示する。
- 表示条件は、テーマがどの経路から入ったかに依存しない。テーマ・外観での手動変更、プリセット適用、テーマファイルのimport、.niatraによる端末引き継ぎ、その他の設定反映でも、現在のテーマが同じリスク判定に該当すれば表示する。
- ボタンを押すと「テーマカラーをリセットしますか？」と確認する。キャンセルでは何も変更しない。「リセット」を確定した場合だけ既定の「レッド（ライト）」配色へ戻して保存する。復旧後は両画面のボタンを非表示にする。通常テーマでは表示しない。
- 確認ポップアップは、ユーザー設定色に依存せず、正式な既定「レッド（ライト）」プリセットから生成したテーマを利用する。リセットのアイコンはパレットと戻す記号を組み合わせる。
- ボタンの文字は黒文字＋白縁取り、アイコンも黒を白で縁取った固定色とする。ボタン外周は黒/白の二重線などで、明るい背景・暗い背景のどちらでも識別できるようにする。これは復旧専用の唯一の固定色例外であり、通常UIのテーマ色を固定してはならない。

### リスク判定の位置づけ

- 判定は実際の描画で重なる文字・アイコンと背景に限り、離れた色項目の総当たり比較はしない。パステル、モノクロ、同系色、同明度・異色相の組み合わせも自由に設定できる。
- 本機能でいう「読めない」は、色面同士の色差が小さいことではなく、**背景の上に描画された重要な文字・アイコンがスマホでもほとんど判読できず、操作の発見・変更が困難になる状態**を意味する。色差ΔE00やOKLab色差はこのリセット判定には使用しない。
- 実装する判定は APCA-W3 (0.0.98G, sRGB) の文字・背景コントラスト値の絶対値 **|Lc| 10未満**（10ちょうどは対象外）とする。正常色覚で計算し、それが閾値以上なら1型・2型・3型二色覚（Machadoらの模擬行列）の条件でも同じ文字色・背景色を変換して計算する。**いずれか1つでも閾値未満なら表示**し、すべて10以上なら非表示とする。判定を通知や文字色の強制補正には使用しない。
- |Lc|10は「文字がある程度読みにくい」という理由でボタンを常駐させず、ユーザーが配色を気に入って使う自由を優先するための**アプリ専用の非常に厳しい暫定ヒューリスティック**。通常のアクセシビリティ合格基準や「誰もが自力復旧できる」保証ではない。APCA計算では生コントラストが一定以下ならLc 0に丸められ、非ゼロの最小値は概ね|Lc|7.3となるため、|Lc|5未満を採用すると主に0だけの判定になってしまう。12px等の小さい文字、フォント・端末特性・明るさ、実UIの文脈で結果が変わる点は別途検証する。
- 判定する実UI上の重要な重なりは、本文文字とパネル背景、メニュー文字とメニュー背景、起動画面のボタン文字/アイコンとアクセント色・選択色、選択中の文字色（必須設定）と選択色との関係。透過色は実際の下地へ合成してから評価し、隣接しない色同士や装飾色同士は評価しない。グラデーション上の場所や文字サイズによる実見え方の差は、製品UIキャプチャで引き続き検証する。
- **軽量化**: 一組ごとに正常色覚で著しく低ければ早期終了し、必要な場合だけ二色覚模擬を実行する。現在のテーマオブジェクト単位で判定値をキャッシュし、画面の再構築・スクロール・アニメーションでは計算しない。カラー設定のプレビュー等でテーマが変更された後にだけ次回参照時再判定する。
- この判定はボタンの表示にのみ使い、保存の可否・エラー・色の巻き戻しには使わない。判定に該当してボタンが表示されても、色を自動補正したり別の値に差し替えたりしない。
- 検証対象のペアは、実UIで操作や復帰に関係する文字色×パネル背景色、文字色×メニュー背景色、主要導線の文字色×背景色などから確認する。全項目の色差を総当たりで強制しない。
- 色相対比・明度対比・彩度対比・補色対比・縁辺対比などは見え方を理解する観点とし、個別の最低色差や保存拒否条件を設けない。彩度0%では色相値を変えても無彩色であること、HSLの明度L=0%/100%は黒/白、HSVのV=0%は黒であることなど、設定値と描画色が一致しないケースも判定の確認時に留意する。
- テーマ色を変更したら保存されること、アプリを再起動しても保持されること、危険判定時に起動画面と「テーマ・外観」の両画面右上へ固定色ボタンが出ること、確認ダイアログでキャンセルすれば保持・リセットを確定した場合だけ標準へ戻ることを実操作で確認する。
