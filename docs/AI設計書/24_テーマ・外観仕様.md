# 24\_テーマ・外観仕様

## 概要

NIARIMではUI全体の外観を自由に変更できる。変更はアプリ全体へ即時反映される。キャンバスデータには影響しない。無料版・プレミアム版共通で利用できる。

---

## カスタマイズ項目

| 項目             | 内容                                     |
| ---------------- | ---------------------------------------- |
| ベーステーマ     | ライト / ダーク / システム設定に合わせる |
| アクセントカラー | ボタン・選択枠・スライダーなどの強調色   |
| 文字色           | UI全体の文字色                           |
| パネル背景色     | レイヤーパネル・ツールパネルなどの背景色 |
| メニュー背景色   | 三点メニュー・ポップアップの背景色       |
| 選択色           | 選択中項目のハイライト色                 |
| 更新マーク色     | ❗アイコンの色                           |

すべてカラーピッカー（HSV / RGB / HEX）で自由に設定できる。

---

## ベーステーマ

| テーマ                 | 内容                        |
| ---------------------- | --------------------------- |
| ライト                 | 白を基調としたUI            |
| ダーク                 | 黒・グレーを基調としたUI    |
| システム設定に合わせる | AndroidのOSテーマ設定へ追従 |

初回起動時の初期値：システム設定に合わせる

---

## アクセントカラー

UIの強調表示に使用する。

## 適用対象例：選択中タブ / 選択枠 / スライダー / ON状態スイッチ / ボタン / 更新マーク / ダイアログの強調色 / タイムラインの現在フレーム

## テーマプリセット

### 保存内容

1つのテーマプリセットには以下を保存する。

- ベーステーマ
- アクセントカラー
- 文字色
- パネル背景色
- メニュー背景色
- 選択色
- 更新マーク色
- （将来追加されるUIカラー設定も含められるよう拡張可能）

### 操作

| 操作           | 内容                                              |
| -------------- | ------------------------------------------------- |
| 新規作成       | 現在の設定を新しいプリセットとして保存            |
| 上書き保存     | 既存プリセットを現在の設定で上書き                |
| 名前変更       | プリセット名を変更                                |
| 複製           | プリセットをコピーして追加                        |
| 削除           | プリセットを削除                                  |
| 並び替え       | ドラッグで順序変更                                |
| お気に入り登録 | よく使うプリセットをお気に入りに登録              |
| 読み込み       | .niathemeファイルを読み込んでプリセット一覧へ追加 |
| 共有           | .niathemeファイルとして書き出して共有             |
| 適用           | タップで即座に反映                                |

### 一覧表示

各プリセットに色設定から自動生成したサンプルUIイメージを表示する。名前だけでなく見た目で選べる。

### 初期プリセット

アプリ初期状態で、虹7色（赤・橙・黄・緑・青・藍・紫）× ライト/ダークの
14種類を用意する。「赤」はアプリの既定色である珊瑚ピンクが該当する。

- ポップ（ライト）＝赤・ライト（既定選択。baseThemeはシステム設定に合わせる）
- ポップ（ダーク）＝赤・ダーク
- オレンジ（ライト／ダーク）
- イエロー（ライト／ダーク）
- グリーン（ライト／ダーク）
- ブルー（ライト／ダーク）
- インディゴ（ライト／ダーク）
- パープル（ライト／ダーク）

## テーマの共有（初期実装）

テーマプリセットを `.niatheme` ファイルとして書き出し・読み込みができる。

### 書き出しフロー

```
テーマプリセット選択
↓
「テーマを書き出し」
↓
.niatheme ファイルを生成
↓
共有
```

### 読み込みフロー

```
.niatheme ファイルを受け取る
↓
プレビュー表示
↓
保存
↓
プリセット一覧へ追加
```

## 引き継ぎ（.niatra）との連携

.niatra による端末移行時にUIテーマプリセットを含めることができる。

```
☑ UIテーマ
☑ ブラシ
☑ パレット
☑ 自動塗りプリセット
☑ 設定
```

新しい端末でも同じ作業環境をそのまま復元できる。クラウド不要・ローカルファイルのみで完結。

## UIテーマとワークスペースの区別

UIテーマとワークスペースは完全に独立した設定である。

| 設定           | 保存内容                                           |
| -------------- | -------------------------------------------------- |
| UIテーマ       | 配色・アイコン・外観のみ（ツール配置は保存しない） |
| ワークスペース | 表示ツール・早替えツール・パネル配置               |

テーマを変更してもワークスペースは変わらない。ワークスペースを変更してもテーマは変わらない。

```
│       ├ ツールバー編集
│       ├ パネル配置
│       └ ワークスペース保存・読込
```

## 色設定の自由度と、操作不能を防ぐ二段階の復旧

テーマ・外観は、ユーザーが自由に色を組み合わせられるようにする機能である。一般的に読みにくい色の組み合わせもユーザーの選択として許容し、標準的なコントラスト比・配色美・アクセシビリティ基準を満たさないという理由だけで保存を拒否しない。拒否条件は、文字とその直下の背景がほぼ同色など、テーマ・外観設定や主要導線を事実上操作不能にして自力で元へ戻せなくなる危険の予防に限定する。

復旧は次の二段階で行う。

1. **テーマ・外観設定内の予防：** カラーピッカー編集中は色をプレビューする。閉じる/確定時に、設定画面の操作や復帰を阻害するほど近似した重要な色ペアが検出された場合、変更前の配色へ戻して理由を表示し、その色の組み合わせを保存しない。一般的な可読性を理想化するための閾値は使わない。
2. **起動画面右上の最終復旧：** .niatra等の外部データ取り込みなど、設定画面内の検証をすり抜けて読めないテーマが入る経路に備え、テーマの配色に依存しない固定色のリセットボタンを起動画面右上に表示する。押すと既定のライトテーマへ戻し、復旧後はボタンを非表示にする。固定色の例外はこの非常用コントロールに限定し、通常UIの色を固定する理由にはしない。

### 閾値の考え方

- 閾値の唯一の目的は「読みにくさ」全般の解消ではなく、ほぼ同色のために復旧操作が失われる状態の予防である。4.5:1等の一般的なコントラスト要件をテーマ色の保存条件として強制しない。
- 対象にする色ペアは、実際に設定・復帰に必要な文字と背景、主要導線の文字とその背景など、操作不能につながる組み合わせに限定する。すべての色項目を総当たり比較しない。
- 現行実装では kMinReadableContrast と readabilityCriticalPairs() を用いて危険な色ペアを判定している。閾値や対象ペアを変更する際は、組み込みプリセット、同色/近似色、一般には読みにくいが操作可能な配色、保存前の復帰、外部データ取り込み、起動画面の復旧ボタンを実際に試して、必要最小限の制約であることを確認する。色相差、彩度差、同時対比の用語だけで拒否を決めない。
