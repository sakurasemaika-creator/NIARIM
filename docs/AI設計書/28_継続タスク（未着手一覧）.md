## 完了：定規ツール「タップしても何も表示されない」バグ（2026年8月21日、原因特定・修正済み）

「実機でないと真偽が確認できない」として保留していた項目のうち、定規ツールについては
実機ログなしでも原因を特定できる静的なロジックバグだったことが判明した。

**原因**：`ruler_panel.dart`の`_defaultRuler()`が、新規定規の初期位置（中心座標・楕円の
半径・消失点）を、1920×1080キャンバスを前提にした**絶対座標のハードコード**
（中心`Offset(960, 540)`、消失点`Offset(200, 540)`等）で生成していた。一方、実際の
キャンバスサイズ（`TileManager.canvasWidth`/`canvasHeight`）は`Project.drawingWidth`/
`drawingHeight`（＝`exportWidth`/`exportHeight` × 描画領域倍率）から決まり、新規プロジェクト
作成画面には1920×1080以外にも1280×720・1080×1080（正方形）・1080×1920（縦長）・
1080×1350・1440×1080の計6種類のサイズプリセットが用意されている（加えて描画領域倍率
が1.0以外なら実際の描画キャンバスはさらに拡張される）。そのため「フルHD（1920×1080）
かつ描画領域倍率1.0」以外のほぼ全てのプロジェクトで、新しく作成した定規がキャンバス外の
的外れな座標に配置されており、ユーザーの目には「定規ツールをタップしても何も表示され
ない」という不具合として映っていたと考えられる。

**修正内容**：`RulerPanel`に`canvasWidth`・`canvasHeight`（実際のキャンバスサイズ）を
必須パラメータとして追加し、`canvas_screen.dart`の`_rulerPanel()`から
`ProjectService.tileManagerOf(widget.projectId)`経由で実際の値を渡すようにした。
`_defaultRuler()`内部では、1920×1080を基準にした従来の座標を`canvasWidth/1920`・
`canvasHeight/1080`の比率でスケーリングすることで、元のデザイン（消失点の配置バランス
等）を保ったまま、どのキャンバスサイズでも定規がキャンバス内に収まる位置に配置される
ようにした。

flutter analyze（70 issues found、0 errors、既存件数から変化なし）・flutter test
（83 tests passed、既存件数から変化なし）で検証済み。実機がないため、実際にキャンバス上で
定規が正しい位置に表示され操作できることは未検証（着手する場合は、フルHD以外のキャンバス
サイズ、特に正方形・縦長のプロジェクトで各種定規を新規作成し、キャンバス内の妥当な位置に
表示されるか確認すること）。

## 未着手：実機でないと真偽が確認できない不具合報告

以下はいずれもコードレビューを複数回実施し、配線・計算式ともに問題は見当たらなかった
（詳細は各項目の記述および`12_実装チェックリスト.md`の追記を参照）。実機のない環境での
静的解析には限界があるため、着手する場合はまず実機での再現確認から始めること。

- **フレーム一覧をタップしても現在地（カレントフレーム）が移動しない**（キャンバスモード側の
  `FrameStripWidget`）。各フレームの`GestureDetector.onTap`は`widget.onFrameSelected(index)`を
  呼び、`canvas_screen.dart`側で`onFrameSelected: (idx) => setState(() => _currentFrame = idx)`と
  正しく配線されている。`IgnorePointer`で囲われた中央の現在フレーム枠（2026年8月20日に
  色固定の赤からテーマの更新マーク色連動へ変更済み、`FrameStripWidget`参照）がタップを
  奪っている可能性も確認したが、`IgnorePointer`はヒットテスト対象から正しく除外される
  ため問題なし。再現するなら実機のログ（onTapが実際に呼ばれているか）から調査すること。
- **フレーム一覧を左右にスワイプしたとき、中央の現在フレーム枠に一番近いフレームへ自動吸着し、
  そのフレームを現在地にする**（タイムラインモードと同じ挙動に揃える）。
  そのときキャンバス・レイヤーパレット・タイムラインモードの表示も連動すること。
  `_scrollToCurrent`の`target = currentFrame * itemExtent`と`_handleScrollEnd`の
  `nearest = (offset / itemExtent).round()`は、`sidePadding = (ビューポート幅-itemExtent)/2`
  を用いた中央揃えの計算式として数式上つじつまが合っている（左右パディング分がちょうど
  打ち消し合う）ことを手計算で確認済み。
- **プレビュー下端のドラッグハンドルを動かすと「表示範囲」が変わってしまい「サイズ」が
  連動しない**という報告が一度あった。`onVerticalDragUpdate`が`_previewHeightDragOverride`を
  更新し、`SizedBox(height: previewHeight, child: _buildPreviewContent())`がその値をそのまま
  高さに反映する配線自体は正しい。ただし2026年8月21日の再調査で、これが実装バグではなく
  `BoxFit.contain`の仕様上避けられない見た目の挙動である可能性が高いことが判明した：
  ドラッグで変えられるのは高さのみで、プレビューの幅は画面幅（スマホは全幅、PC/DeXは
  `LayoutBuilder`で最大640pxに制限）に固定されたままのため、映像のアスペクト比によっては
  ある高さを超えると`BoxFit.contain`のレターボックス（上下の余白）が増えるだけで映像本体は
  それ以上大きくならない。ユーザーからは「ドラッグしても映像が大きくならず、代わりに
  余白（＝表示範囲）だけ変わる」ように見えるはずで、報告内容と一致する。これは
  「サイズ変更ハンドルなのに高さしか変えられない」という設計上の制約であり、単純な
  コード修正では解決できない（映像本体を追従して大きくしたければ幅も連動して変える設計
  変更が必要）。着手する場合は「高さが伸びても映像本体が大きくならない地点がある」という
  仕様として実機で確認した上で、対応するか・仕様として許容するかをまず判断すること。
- **チュートリアルの吹き出しがどこをタップしても消えない**という報告があったが、
  `first_use_tooltip.dart`を確認した限り、既に全画面の透明バリアで「どこでも閉じられる」
  実装になっていた。過去に修正した多重表示バグが原因だった可能性がある。
