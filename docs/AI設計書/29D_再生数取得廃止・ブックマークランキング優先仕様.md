# 29D  YouTube統計取得廃止・NIARIM独自ランキング仕様（2026-11-05）

> **この決定は29/29Cの「YouTube再生回数を取得しランキングに用いる」仕様に優先する。** NIARIMの最新版は `dev_branch`。旧YouTube統計バッチのソースは一部テスト用に残っていても、CDKスタックからLambda・EventBridge定期起動を除外する。

## 1. 決定事項

1. **YouTube再生数・高評価・コメント数の定期取得は行わない**。関連数値はNIARIM UIにも表示しない。以前の再生数ランキング・期間別再生数ランキング・再生数から計算する年間アワードは撤回する。
2. **NIARIM独自のブックマーク数のみをランキングの指標とする**。現在はGSI2で累計ブックマーク数の上位50件を取得し、ユーザーが登録・解除した時点でDBを更新する（GSIは結果整合性でわずかな反映遅延がある）。集計にYouTube APIを使わない。
3. 日・週・月・年のブックマーク順位は、正確な集計期間内の「新規ブックマーク数」や「純増数」の定義を固定し、操作イベント履歴／期間別カウンタを実装してから提供する。**いまは未実装として明示し、再生数Top50をブックマークで並べ直した偽のランキングは提供しない**。
4. 新着、作者別一覧、タグ、ブックマーク、フォロー、コイン、ミッションはユーザーの操作時にDBで処理する。これらのためにYouTube統計を取得しない。
5. 投稿動画は端末からYouTubeに直接アップロードする。投稿登録の所有者確認にはYouTube `videos.list(part=snippet,status)` を使用するが、`statistics`は要求しない。YouTube埋め込みプレーヤー本体の動画配信をNIARIMサーバーで中継しない。
6. 現在の再生前`videos.list`チェックはまだ残る。実プレーヤーと`onError`を実装し、NIARIM独自の公開・退会状態をサーバー側で検証した後に、このYouTubeチェックを撤去する。
7. YouTubeチャンネル名・アイコンは初投稿時にキャッシュし、手動更新をJST日付あたり成功1回までとする。YouTube統計とは別の通信である。

## 2. YouTube作品タイトル・概要欄の方針（要実装）

- `videos.list(part=snippet)`で`title`、`description`、`thumbnails`を取得できる。既存の投稿登録処理は同じ呼び出しでタイトル・サムネイルを取得しているため、`description`を追加しても呼び出し回数は増えない。
- ただしYouTube APIから取得したメタデータは、一般に30日以内に更新または削除する必要がある。
- **推奨**：NIARIM投稿画面でユーザーが独立した「作品タイトル」「作品説明」を入力し、NIARIM独自コンテンツとして保存し、同じ値を本人の明示的な投稿操作でYouTubeに送信する。こうすれば利用者が入力したNIARIM作品データとして保持でき、YouTubeの変更・失効やAPI30日ルールに常時依存しない。
- YouTube側で後から名前や概要を変更した場合は、NIARIMの作品タイトル・説明も自動同期したとは表示しない。YouTube由来のサムネイルや名前の保持・更新規則は引き続き個別に順守する。投稿時のNIARIM独自説明欄はまだ未実装。

## 3. データベースの変更

- DynamoDB Standard provisionedの無料枠は25 RCU・25 WCU。
- 構成からGSI1（再生数順）2 RCU/2 WCUを除外し、既存GSI2（ブックマーク数順）を引き続き使う。予定割り当ては**23 RCU・23 WCU**（15本体＋GSI合計8）。
- CDKスタックからYouTube統計更新専用LambdaとEventBridge定期実行を除外する。実際のAWS上で停止するのは構成をデプロイしたときであり、ソース修正だけで既存AWS環境へ操作したことにはならない。
- 既存レコードに残る古いviewCount/likeCount/commentCountやランキング関連属性は表示せず、将来移行時に安全に整理する。新規投稿のゼロ値も互換のため当面残るが、定期更新しない。
- GSIの追加や作者別並べ替えは、残り2 RCU・2 WCUと、基表の容量を配分するか事前計算の一覧で処理するかを比較してから進める。

## 4. 応援コイン・応援ランキングは不採用（2026-11-05確定）

- **コインを他ユーザー・作品へ贈る機能は作らない**。既存コインは今までの本人向け報酬・交換用途を維持し、譲渡可能な残高にはしない。
- **応援ランキング・応援メッセージの保存も追加しない**。DynamoDBの容量・読み書きを増やさず、NIARIM独自のブックマークを作品評価の指標とする。
- 再検討は新たなユーザー指示がある場合に限る。

## 4.1 YouTubeコメント連携の調査事項（未採用・未実装）

- YouTube Data APIでコメント閲覧（`commentThreads.list` 1ユニット、追加返信`comments.list` 1ユニット）、投稿（`commentThreads.insert` 50ユニット）、返信（`comments.insert` 50ユニット）は可能。
- 投稿・返信にはユーザー本人のYouTube OAuthと `youtube.force-ssl` が必要。すべてYouTubeへの投稿と明示し、同意した時のみ送信する。ログイン済みのGoogleアカウントとYouTubeチャンネルの認証・失効に留意する。
- YouTubeコメント本文をNIARIM DBに長期保存しない。YouTube APIデータの30日以内の更新／削除要件と、削除済みコメントを残さない要件を守る。
- 共通クォータ10,000ユニット/日の範囲では投稿・返信合計200件で理論上上限になる（その他のYouTube API利用量を除く）。閲覧のみの段階導入や公式YouTubeへのリンク誘導も比較してから採否を判断する。
