# 13A リワード広告・コインによる期間限定解放仕様

> 2026-11-04 改訂：チェックボックス複数選択＋**全選択に共通の1つの期間**、リワード／サブスクの重複時の残時間保護、全機能＋全広告なしの収益下限、一括商品の「最もお得」表示を規定。**設計段階・本番実装未完了**。旧版の「項目ごとの個別期間」および「全機能一括割引」は廃止する。既存の `13_広告・課金仕様.md` と併読。

## 0. 収益モデル・前提

- 無料会員は通常広告、プレミアム会員は月550円（税込）／年5,500円（税込）で広告なし＋全Premium機能。リワード広告は**明示的に選んだ人にのみ**全画面表示する。
- 広告を完了すると、当該ユーザーにのみ使用できる非換金・非譲渡のアプリ内コインを付与する。コインで「機能別」「広告枠別」「全広告なし」「全機能＋全広告なし」の期間限定権利を交換可能にする。全機能解放の長期期間も原則として選択肢から排除しないが、必要広告視聴数と供給可能性を正直に提示する。
- **全機能＋全広告なしにはコイン割引を設けない**。同じ期間・提供条件の現金サブスクの実際の開発者側純利益を下回らないことを価格設計上の下限とし、広告非表示による失収益・運用費も積み増す。各個別カスタムは同じ条件で束ねた際に一括商品より割高となるように価格設計する。UIの「最もお得」バッジは**コイン交換商品同士で同一期間・同等の権利範囲**を比較して割安な場合に一括商品へ一つだけ表示し、現金サブスクよりお得と誤認させない。
- **実広告収益は確定前に変動し、広告が配信されない可能性もあるため、固定のコイン枚数・固定の広告視聴回数で「課金時以上の実利益」を無条件保証することはできない**。保証を求める場合、収益確定済みの広告視聴に裏付けられたサーバー台帳のみを交換可能残高に計上し、実測コスト・純利益の保守的検証と収益下限ガードを満たす場合にのみ全機能交換を許可する。見積もり・収益統計だけでは保証を主張しない。広告視聴回数目安は非保証で明示する。
- 視聴で獲得するコインのレート、交換レート、価格表バージョン、国・年齢等による広告供給条件はサーバーで管理する。適用中の単価を広告表示**前**に必ず表示する。取得済みコインの価値を予告なく切り下げない。
- **2026年末固定のリリースキャンペーン**は廃止候補。今回の仕様更新だけでは `monetization_gate.dart` を削除せず、本番広告／課金を有効化しない。公開日や税務・ストア設定が確定したときにキャンペーンを正式に撤廃し、テスト広告環境と本番を分離する。

権限は画面内に直接列挙して終わりにせず、全画面・各サービスのゲートと紐づく**統一カタログ**を設ける。新機能が追加されたら必ずここへ追記し、課金／リワード双方の解放範囲、画面テキスト、テストを同時更新する。

10. その他の現在／将来のPremium限定機能は、コード・設計書・バックエンドを照合して一覧登録する。実装・検証前の項目は選択不能・準備中表示とし、存在しない特典の対価としてコインを徴収しない。

※ EndCard編集とEndCard削除、ウォーターマーク登録と追加など、**同じ基礎権限の操作を二重の有料商品として請求しない**。投稿数緩和もアップロード／リポストなどの権限の境界を整理する。

## 2. 画面構成

### 入口とメイン画面

プロジェクト一覧の右側ハンバーガーメニュー「無料で有料会員限定機能を使う」→リワード画面。メニュー名は全対応言語に翻訳し、現在テーマ由来の色・くらむぼん等のフォント方針を維持。

1. 画面最上部に**現在利用中の特典**：サブスク由来／リワード由来／保存中・再開待ちを区別。各項目の有効期限・残り利用時間を表示する。複数箇所の権限を同じ画面から確認可能とする。
2. その下に**目標に設定したシミュレーション**を表示。選択した特典と共通期間、現在の見積もりバージョンを保存し、編集／解除可。
3. 「保有コイン / 目標コイン」＋プログレスバー。達成時はテーマ色に従う専用達成デザイン＋「目標達成」「今すぐ解放」ボタンに切替。達成しても自動消費・自動有効化しない。100%超の値を数値として保持し、バー自体は100%に制限。配慮されたモーション・読み上げラベル。
4. コイン残高、視聴前に示す獲得枚数、リワード視聴ボタン、シミュレーションへの導線、コイン履歴、Premium会員登録を表示。広告の未ロード・未同意・年齢制限・回数上限・キャンペーン停止時は理由を表示して視聴不可。
5. 利用権の一括パックには**一つだけ**「最もお得」バッジ。価格比較に根拠がある場合のみ表示。

### シミュレーション（共通期間）

1. **複数の特典をチェックボックスで選択する**（機能別／広告枠別／広告一括／全機能＋全広告なし）。
2. **共通の利用期間を一つだけ選ぶ**。すべての選択項目へ同じ延長時間を適用する。機能ごとの時間入力は設置しない。
3. 合計必要コイン数と保有・不足コイン数、必要視聴回数の目安、各項目の開始・終了予定、重複特典の延長対象を見やすく表示する。
4. 「このコイン枚数を目標にする」は現在の組み合わせと期間・価格バージョンを保存する。残高が十分なら「コインと引き換え」も表示。ただし正式見積もりをサーバーで再照合し、確認画面と確定操作を経ること。
5. 月額／年額Premiumと異なりコインを貯める手間があること、現金への換金はできないことを説明する。広告を無理に連続視聴させる文言・偽の時間制限は使わない。

### 期間の指定

| UI選択肢 | 刻み |
| --- | --- |
| 1〜24時間 | 1時間刻み |
| 2〜6日 | 1日刻み |
| 1〜3週間 | 1週間刻み |
| 1か月以上 | 1か月刻み |

1日=24時間、1週=7日、**月=暦月**（月末は翌月末へ丸める）。7日・4週間付近では表示上の区切りと実際の日数・料金の逆転がないように計算し、期限日時を明示。長期上限はサーバー設定から取得し、不正・負数・重複値を拒否する。広告の供給上限が目標達成見込みに影響する場合、現実的な到達目安を断定しない。

## 3. 重複期間・サブスク加入の扱い

### リワード権利 × 新しいリワード交換

- 同じ権利に**残り時間がある場合は、その残時間の後ろに新規購入した共通期間を積み増す**。他の新規権利は交換確定時から開始する。同じ見積もり内でも最終的な有効期限が異なる場合があるため、一覧に個別の予想期限を表示する。
- 重複時に無条件で追加コインを徴収したり、交換を全面禁止したりしない。既存権利の残り時間を提示し「この特典は○○まで利用可能です。追加分はその後から○○まで延長されます」と**交換確定前**に表示。
- 権利が既に使えることを隠して販売しない。既存権利が使えるだけでよい場合は対象の選択を外せるようにする。重複解消はサーバー側で原子的に確定し、同時交換での二重加算を防ぐ。
- **全広告非表示**を新規解放中は個別広告権利の残時間を保全し、全広告期間終了後に残り分が再開する。**全機能＋全広告なし**を新規解放した場合も被覆する個別リワード権利を一時停止・保存し、一括期間終了後に再開する。バンドル同士の重複も同様。カバーされている時間は二重消費しない。
- 保存中／再開待ちの権利、延期した期間が見積もり・有効期限・画面に反映されること。既存の期限切れと同時発生する新権利に隙間が生じないこと。

### リワード権利 × 有料サブスク

- **ユーザーがサブスク購入を開始した時点ではなく、ストアで契約有効が確定した時点**で、サブスクに含まれるすべてのリワード権利の**残り利用時間を凍結**する。購入未完了・失敗・保留中は凍結しない。
- サブスクが継続している間、リワード権利は「保存中（残○時間）」として保持。契約の更新／解約予定によってコイン・時間を失わせない。
- 有料サブスクが実際に失効した後に、凍結した残時間が自動再開される。ユーザーに不利な「特典が無効になります」と表示するのではなく、購入画面に「今あるコイン特典の残り時間は保存され、Premiumの終了後に再開されます」と簡潔かつ正確に表示する。**解約ボタンを押しただけで再開しない**。継続中は保存し続ける。
- サブスクで既に提供中の権利はコイン交換画面では「会員特典で利用中／交換不要」として交換を防止する。サブスク登録時にコイン残高を消費したり消滅させたりしない。
- コイン全機能パスとの組み合わせでも同じ意味の権利を二重に消費させない。
- 時間単位で区切れない投稿回数等の**クォータ権利**はカウント期間と上限を別管理し、過去の投稿を取り消さない。プレミアム投稿枠を時間単位で解放する設計は連投・スパム対策をサーバー側で適用したうえで検証する。

## 4. 見積もり・価格設計（サーバーで最終確定）

- 全機能＋全広告なしは、**単一パック価格**で独立販売する。任意の月数なら同じ月数の月額サブスクの開発者側純利益、12か月なら年額サブスクの純利益を収益下限の比較対象とし、期待するバナー／処理中広告の減収と追加運用費も見積もる。月額と年額の比較期間、残存広告価値、税・実際のストア手数料、返金、広告の無効トラフィック調整、広告の最終収益確定も考慮する。
- 計算例：`目標最低収益 = 対象期間のサブスク純利益 + 非表示広告の想定逸失純利益 + 追加運用費 + 安全余裕`。`最低必要コイン = ceil(目標最低収益 ÷ コイン1枚あたりの**実現・保守的に検証された**広告純収益)`。これは**目標値**であり、eCPM見積もりしかない段階では絶対保証ではない。外部から持ち込めるコインや二重付与があると原価保証できないため、収益帰属の台帳が必要。
- 固定「1広告○コイン」は広告の国・年齢・需要差があるため、収益保証との両立に限界がある。実現純収益に裏付けられた残高のみ全機能交換可能とする**収益保証用の別残高管理**、または保守的なレートと十分な安全余裕を検討。最終確定前に「絶対に同額利益」と広告表示しない。
- 個別カスタムの合計価格は**同一権利範囲・同一期間**の全機能パックより割高に設定してよいが、個別1機能だけなら一括パックより安く試せること。バンドル選択時は重複するチェック項目を自動解除する／別選択不可にする。個別すべてを選択したケースが全機能パックより高ければ「最もお得」バッジはパックに表示。
- 価格表には `priceVersion`、全Premium価格・個別価格・対象期間・比較根拠、収益ガードの有効／無効を保持。サーバーが当時の見積もりを固定し、コイン交換確定前に再見積もり（旧目標から無断変更しない）。価格改定は次回以降の交換に適用し、獲得済み特典・残時間を削らない。
- 視聴が困難な場合でも、無料の基本機能を不必要に制限しない。サブスクのメリットは広告を大量に見る必要がないこと・自動更新・継続使用の簡便さと明確にする。

## 5. バックエンド／実装要求

- `AdProvider` / `AdMobProvider` にリワード広告を追加し、画面は `AdvertisingService` 経由とする。SSV（Google署名検証・transaction_id一意制約）で二重付与を防止。画面の `onUserEarnedReward` コールバックだけで交換可能残高を増やさない。
- `WalletLedger`（発行・保留・確定・消費・返還）と `EntitlementLedger`（対象権利・取得源・残秒／期限・凍結状態・重複保護）をサーバー管理。アカウント変更・再インストール・複数端末・二重タップ・時計変更・通信失敗を考慮。購入確認もサーバー側でストア領収情報を検証してから契約有効化する。
- 現行 `PremiumService.isFeatureAvailable` の全機能一括判定を、**加入中 OR キャンペーン中（残る間） OR 該当リワード権利有効**へ拡張する。広告も画面位置ごとに非表示を判定。リワード全機能は有料契約状態 `hasPurchasedPremium` と混同しない。
- チェックボックスの同一期間見積もりは `CoinUnlockQuote` を表示用の純粋モデルとして用い、本番消費・有効期限・重複積み増しは認証付きサーバートランザクションでのみ確定。
- 価格が収益下限を満たさない／権利が未実装／子ども向け広告に適合しない／適法な広告がない場合は**交換可能と表示しない**。未完成のPremium機能まで「全機能」として誤記しない。
- 全言語ローカライズ、スマホ縦／PC横／DeX、28テーマ＋カスタムの色に従う。独自の強調色を固定しない。広告消去時は広告の空白を残さない。

## 6. 子どもの利用と広告規約

- 小学生を想定して広告視聴を長時間促進する誘導はしない。未成年向け広告、ユーザープライバシー、広告表示形式、年齢別処理は**Google Play Families**の対象判定に従う。子ども／年齢不明への広告では対応する認定SDK、非パーソナライズ、適切な広告内容が必要。通常操作を妨げるリワード広告の閉じ方なども規約に従う。地域の法令・親の同意が必要な場合はそれも満たす。
- リワード視聴前に得られるコイン枚数・視聴条件を明確に表示し、同意しない場合でも通常利用を妨げない。広告の報酬はアプリ内でのみ使用でき、現金・外部商品・譲渡に使用できない。
