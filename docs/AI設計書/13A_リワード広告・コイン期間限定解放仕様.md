# 13A リワード広告・コインによる期間限定解放仕様（2026-11-04 提案）

> 状態：仕様追加・実装未完了。金額・広告視聴あたりのコイン枚数・交換レートは未決定。実測収益に基づく設定が確定するまで本番の付与・消費を有効にしない。既存の `13_広告・課金仕様.md` と併読する。

## 1. 基本方針と既存設計との整合

- 通常の操作・保存・描画・書き出し中に強制的な全画面広告を挿入しない。全画面広告は明示的な視聴操作による「リワード広告」のみ。
- プロジェクト一覧のハンバーガーメニューへ **「無料で有料会員限定機能を使う」** を追加し、専用画面を開く。プレミアム登録は引き続き別導線で提供する。
- 無料会員は既存のバナー・処理中広告を表示。コインで機能別・広告枠別・全広告・全機能＋全広告を期間限定解放できる。月額・年額Premiumはコイン管理・視聴の必要なし。
- 既存の `isMonetizationEnabled` が false（2027-01-01 00:00 より前）の場合はリワード広告のロード／表示・広告SDK初期化・コイン付与を **行わない**。この期間は既存のリリース記念キャンペーンによりPremium機能を無料開放する。将来の交換条件は参考表示可。ただし「今広告を見られる」「今コインを稼げる」とは表示しない。
- 配色・文字・背景・枠・進捗表示・達成演出はすべて Theme / ColorScheme の値を参照し、独自の固定カラーを追加しない。既存の多言語とSP/PCレイアウトに対応する。

## 2. 画面構成と状態

### 入口・メイン画面

ハンバーガーメニュー「無料で有料会員限定機能を使う」→ コイン／解放画面（戻るでプロジェクト一覧）。

1. 上部：保存した「目標の組み合わせ」を種類・対象・期間が分かる形で列挙する。目標がない場合は「シミュレーションから目標を作成」と案内する。目標変更・解除を可能にする。
2. その下：**保有枚数 / 必要枚数**（例：42 / 100枚）、目標達成率を示すプログレスバー。視覚情報だけでなく読み上げ可能な文字で表示し、100％を超える場合はバーを100％に丸める。超過枚数は数値として保持。
3. 目標達成時：同じ位置をテーマ準拠の達成時専用表示に切り替え、「目標達成」「今すぐ解放」の案内と操作ボタンを出す。達成条件は `balance >= latestConfirmedQuote`、演出は低刺激・モーション削減設定に対応。達成前の文言・装飾と区別しつつ固定色禁止。
4. **目標達成だけでは自動でコインを消費しない／期限付き解放を開始しない**。利用したいタイミングでユーザーが「今すぐ解放」を押し、確認すると開始する。期限付き機能を必要な作業時まで温存できるようにする。
5. 保有コイン、視聴による獲得枚数（実際の設定値）、視聴ボタン。広告が未ロード・同意未取得・上限到達・ネットワーク不良・キャンペーン中なら理由を示して押せないようにする。ユーザーの「見る」押下以外では開かない。
6. 「解放シミュレーション」「現在有効な解放（期限・対象）」「コイン履歴」「Premium（月額・年額）を比較」を用意する。視聴を強要する文言・視聴を煽る偽カウントダウンは使わない。

### シミュレーション画面

- 複数項目を選択でき、項目ごとに個別の利用期間を変更できる。
- 機能別の対象：EndCard編集／削除、ユーザーウォーターマーク、トーンカーブ、レベル補正、プロジェクト尺制限解除、カスタム自動処理など、`PremiumFeature` の現行・将来の全項目に追従する。一つの内部権限が複数UIに関係する場合は二重課金しない。
- 広告枠別の対象：プロジェクト一覧のバナー、キャンバス上部バナー、タイムライン下部バナー、処理中の正方形広告（既存の配置に対応）。
- 一括商品：**すべての広告を非表示**／**Premium相当（全機能開放＋全広告非表示）**。一括商品が個別項目を包含する場合は重複コストを加算しない。より長い個別期間がある場合は、バンドルが覆わない残余期間のみを計算するか、選択の競合として明示してユーザーに解消させる。
- 対象＋期間＋金額を随時再計算。結果には総コイン枚数、保有コイン、不足枚数、必要な広告視聴回数の目安（コイン/回が確定している場合）、利用期間・解放対象を表示。予想収益や広告在庫・視聴時間は保証しない。
- 結果に **「このコイン枚数を目標にする」** ボタンを設置。目標には金額だけでなく、項目・対象画面・期間・価格設定バージョンを保存する。再開後も表示する。価格改定後は黙って目標金額を書き換えず、新見積もりを示して再設定を案内する。
- 保有コインが不足するときは購入／交換を押せないようにし、「目標にする」は可能にする。
- 十分な残高がある場合は確定画面で対象・期間・失効時刻・消費枚数を再掲し、明示的に確定後、バックエンドで原子的に消費／権限付与を実行する。

## 3. 期間の指定

| 表示区間 | 刻み | 選択例 |
| --- | --- | --- |
| 1〜24時間 | 1時間 | 1時間、2時間、…、24時間 |
| 24時間超〜7日未満 | 1日 | 2日、3日、…、6日 |
| 7日以上〜4週間未満 | 1週間 | 1週間、2週間、3週間 |
| 4週間以上 | 1か月 | 1か月、2か月、… |

- 24時間を1日、7日を1週間、4週間から1か月表示へ移す際に単位境界で価格が逆転しないようにする。
- 「1か月」はユーザーが理解しやすい暦月方式を推奨。開始日時と同じ日・時刻を翌月に対応させ、月末に同日がない場合は月末に丸める。4週間から1か月への切替時は実際の失効日時を確認画面で示す。サーバー時刻で権限期限を確定する。
- 各期間には上限を設け、過大な整数・不正な値・負数・0・端数・オーバーフローを拒否する。上限・割引はサーバーの価格表から取得する。
- 既存の解放を再購入する場合は残存期間を不利益なく扱う（有効期限を現在時刻ではなく `max(now, currentExpiry)` から延長）。同じ権限の重複請求を防止する。

## 4. コイン経済・価格表（値は未確定）

- 広告完了による付与枚数、機能別1時間/1日/1週/1か月の交換枚数、広告枠別の交換枚数、全広告・全Premiumの一括交換枚数、上限、割引、通貨単位を **設定データとして一元管理** する。
- 未測定のeCPMから推測した架空の数値を本番価格として固定しない。公開後の国別実収益・視聴完了率・広告在庫・サブスクとの比較で調整する。コインは換金・譲渡・外部決済・ユーザー間送金不可、NIARIM内部でのみ使用。
- 値付けの妥当性チェック：`想定視聴回数 = 必要コイン / 1回の付与コイン`、`推定広告収益 = 想定視聴回数 × 実測1完了あたりの純収益`。長期の全機能解放・全広告非表示が月額550円／年額5,500円の持続可能性を損なわないか検証する。
- コインの有効期限や広告の1日上限を設ける場合は視聴前に明示する。後出しの条件・広告未配信時の不利益・視聴前後の報酬変更を避ける。
- 有効なプレミアム契約中も視聴を強制しない。既に契約で解放済みの権利へ重複コイン消費させない。

## 5. 技術設計・信頼境界

- UI → `CoinWalletService`（表示用）／`UnlockQuoteService`（シミュレーション）／`EntitlementService`（利用権判定）を通じる。既存の `AdvertisingService` と `PremiumService` の責任を保つ。
- 広告の配信プロバイダーは既存の `AdProvider` / `AdMobProvider` を拡張する。画面から直接 `RewardedAd` を扱わない。テスト広告IDを使い、本番移行時に個別設定する。
- コイン付与：広告SDK `onUserEarnedReward` のみをアプリで観測し、**本番台帳の残高確定はバックエンドでAdMob SSV（署名・user_id/custom_data・transaction_id重複検査）を検証した後** とする。コイン残高・有効期限・利用権をローカルのみで確定しない。SSVの遅延中は「確認中」とする。重複通知・再試行でも二重付与しない。
- 消費：認証済みユーザーの残高確認、見積ID/バージョン・対象・期間の再検証、コイン減算・権限記録を単一サーバートランザクションで実施。冪等キーを用いて多重タップ／再送に対応。
- 日時：端末時刻変更で権限を延長できないよう、サーバー側のUTC期限を正とする。オフライン時の表示・一時利用猶予と、期限切れ後の編集・保存・書き出し時の安全動作を定義する。
- 会員判定：`hasPurchasedPremium` は実際の契約に限定。個別利用権判定は `isFeatureAvailable(feature)` を通じ、`subscription OR launchCampaign OR coinEntitlement(feature)`。広告判定は `shouldShowAdsAt(placement)` など配置ごとに分割し、`subscription OR launchCampaign OR allAdsEntitlement OR adPlacementEntitlement` で広告を隠す。コインでの全機能解放を購入済み契約として偽装しない。
- UIの切替やプレビューと実際の権限は同じ単一情報源を使い、背景広告・編集領域のレイアウト再計算を含める。終了時は制作物を削除せず、Premium専用操作や制限を再適用する。
- 翻訳：現在サポートする全ロケールのARBへ文字列追加。テーマ・外観の28種＋カスタム、縦／横／DeX、読み上げ、文字拡大を確認する。

## 6. 広告規約上の制約

- Google AdMobのリワード広告は、**広告の表示より前に毎回、視聴条件とコイン報酬を明示し、ユーザーの明確なオプトインを得る**。閉じる・視聴しない選択で通常機能を妨害しない。視聴中断に対して付与を約束せず、広告側が完了と認めた場合のみ報酬処理する。
- コインはアプリ内の非譲渡・非換金型の間接的報酬とする。外部商品や現金等には交換不可。
- Google公式ドキュメント：
  - https://support.google.com/admob/answer/7313578
  - https://developers.google.com/admob/flutter/rewarded
  - https://developers.google.com/admob/flutter/ssv

## 7. 実装の完了条件・テスト

1. 既存の課金一時停止期間中にリワード広告SDKを初期化しない、ボタンで広告を出せない、コインを付与しない。
2. 許諾なし・未ロード・中断・エラー・二重コールバックではコインを付与しない。SSV重複transaction_idは無害。
3. 1時間刻み・日／週／月境界、月末・うるう年、複数機能＋一括商品の重複排除、価格改定、特典の延長をテスト。
4. 目標変更・削除・再起動後復元・未達／達成（0%、100%、100%超）・価格改定時の警告をテスト。
5. 同時端末／二重タップ／残高不足／通信切断時に二重消費・部分付与が起きない。
6. 個別広告枠と全広告非表示で、実際の広告だけが消え、余白が残らず描画領域が広がる。
7. 購入済みPremium、キャンペーン中、コインPremium相当、個別権限を正しく区別し、既存機能（90秒制限、エンドカード、トーンカーブ、レベル補正、ウォーターマーク、カスタム自動処理）に回帰なし。
8. 全テーマ・各言語・SP/PCのメニュー／画面／達成表示／確認ダイアログを実機で検証し、証跡を保存。
