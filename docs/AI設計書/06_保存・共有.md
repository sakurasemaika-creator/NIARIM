# 06_保存・共有

## 保存の分類

```
保存
├─ アニメ保存（動画書き出し）
│
└─ プロジェクト保存
    ├─ 自動保存（Autosave）
    └─ 手動保存
         ├─ セーブスロット方式
         └─ セーブツリー方式
```

## ファイル形式

| 形式 | 用途 |
|------|------|
| .mirapro | 通常プロジェクト保存（編集用） |
| .mirashare | 共有用（複製してプロジェクトへ追加） |
| .miratra | 引き継ぎ用（旧称 .stutra） |
| MP4 | 動画書き出し |
| GIF | 書き出し時のみ（GIFモードは存在しない） |
| 透過WebM | 動画書き出し（アルファチャンネル保持） |
| .miratheme | UIテーマ共有用 |

## 動画書き出しエンコーダー（ライセンス・特許対応）

- **MP4（H.264）**：Android標準のハードウェアエンコーダー（MediaCodec、
  `android/app`側のネイティブ実装`HardwareVideoEncoder.kt`）で生成する。
  FFmpeg/libx264（GPLライセンス）は使用しない。理由は2点：
  1. libx264はGPLのため、アプリへ組み込んで配布するとコピーレフト
     （対応ソースコード開示義務等）への対応が必要になる
  2. アプリが自前のソフトウェアエンコーダーでH.264を生成する場合、
     H.264規格自体の特許ロイヤリティ（Via Licensing Allianceが管理する
     AVC特許プール）の当事者になり得る。ハードウェアエンコーダーは
     端末メーカー・OSベンダー側で特許処理済みという前提に乗れるため、
     アプリ側の特許論点を回避できる
- **透過WebM（VP9）**：引き続きFFmpeg（`ffmpeg_kit_flutter_new_min_gpl`）
  を使用する。VP9自体・libvpxはロイヤリティフリー/BSDで問題ないが、
  同梱パッケージ自体はGPL 3.0のまま（非GPL版`_video`への切替を試みたが、
  R8有効ビルドで実機起動時クラッシュが続き、Kotlin側の例外ハンドラーでも
  捕捉できない＝ネイティブレベルのクラッシュの疑いがあるため、動作実績
  のある現行版へ再度戻した。詳細は12_実装チェックリスト.mdの追記を
  参照）。

（経緯）MP4のMediaCodec化・WebM用FFmpegの非GPL化は一度、実機
（Android 16）での起動時クラッシュを疑われ全面revertされたが、後の
調査でクラッシュの一因はリリースビルドのR8（HardwareVideoEncoderの
INSTANCEフィールド除去）と判明し修正した。しかしR8有効ビルドでの実機
クラッシュは修正後も継続しており、原因切り分けのためWebM用FFmpeg
パッケージのみ再度GPL版へ戻している状態。非GPL化は原因が完全に
特定でき次第、再挑戦する。
- 無料版のエンドカード（MIRANIMAロゴ、約5秒）は、本編動画への後結合
  ではなく、フレーム生成の段階でフレーム列の末尾へ追加してから
  一括エンコードする（`dart:ui`のテキスト描画で都度生成。FFmpegの
  drawtext/concatフィルターには依存しない）。

## 自動保存（Autosave）

- 描画などで変更が発生したタイミングで自動保存
- クラッシュ・ファイル破損時の復元専用
- 最大3件固定・古い順に自動削除
- Undo履歴とは別管理
- 手動保存（セーブスロット・セーブツリー）とは完全に独立

---

## 手動保存

### 保存方式

設定から保存方式を選択できる。

| 方式 | 内容 |
|------|------|
| セーブスロット方式 | 固定数のスロットに保存。スロット数は設定から変更可能 |
| セーブツリー方式 | 保存データを履歴（ツリー）形式で管理。保存数に制限なし |

### セーブスロット方式

| 品質 | 最大件数 |
|------|---------|
| 低品質 | 5件 |
| 中品質 | 10件 |

- 保存先スロットはユーザーが選択する（自動上書きしない）
- 各スロットにサムネイル・保存日時・任意のセーブ名を表示

### セーブツリー方式（高品質）

- 保存数無制限
- 任意でセーブ名を付けられる
- 過去のセーブ地点へ戻って保存すると枝分かれする
- 元の最新セーブは消えない

詳細は 23_セーブツリー仕様.md を参照。

### 保存方式変更・スロット数変更

以下の場合は保存データ変更画面を表示する。

- セーブツリー → セーブスロット
- セーブスロット数を減らす
- 保存データ数が変更後の保存上限を超える

スロット数を増やす場合は表示しない。

詳細は 23_セーブツリー仕様.md を参照。

## 保存プリセット

保存プリセットは品質・保存方式・その他保存設定をまとめて保持するプリセット。

- ブラシプリセット・自動塗りプリセット・UIテーマプリセットとは完全独立

### 保存設定画面の流れ

```
品質設定
↓
端末スペック別おすすめ
  ・低品質
  ・中品質
  ・高品質
↓
プリセット自動適用

または

品質設定
↓
カスタム
↓
保存方式
↓
各詳細設定
```

デフォルトはプリセット表示。「カスタム」をタップするとアコーディオン展開で詳細設定が表示される。

---

## Undo

- デフォルト50回
- 設定変更可
- プロジェクト保存時に保存しない
- 自動保存とは独立

---

## 共有フロー（.mirashare）

```
.mirashare作成
↓
端末に保存
↓
受信側がタップ → MIRANIMAで開く
↓
確認ダイアログ
「この共有ファイルを複製して通常プロジェクトとして保存しますか？」
↓
プロジェクトタブへ追加
（.mirashare自体は変更されない）
```

---

## 引き継ぎ（.miratra）

引き継ぐ項目をチェックボックスで選択できる。

```
☑ 設定
☑ 素材
☑ ブラシ
☑ プリセット
☑ UIテーマ

[全選択]  [全解除]
```

---

## ゴミ箱

- 削除したプロジェクトはゴミ箱タブへ移動
- ゴミ箱一覧でサムネイル・削除日時を表示
- 復元：元の場所へ戻す
- 完全削除：確認ダイアログを表示してから削除

```
完全に削除しますか？
元に戻すことはできません。

[キャンセル]  [削除]
```

- 自動削除設定：OFF / 30日 / 60日 / 90日（設定画面で変更可能）

## EndCard Track（エンドロゴ）

動画書き出し時、本編終了後にMIRANIMAロゴ動画（約5秒）を自動追加する。

```
ユーザー作品（本編）
↓
本編終了
↓
MIRANIMAロゴ動画（約5秒）
↓
動画終了
```

- 本編アニメーション部分には一切表示しない
- 内部的にEndCard Trackとして管理

| 版 | 状態 |
|----|------|
| 無料版 | タイムライン上に南京錠付きで表示。タップするとPremium誘導ダイアログを表示。削除・移動・編集・操作不可 |
| プレミアム | 南京錠が解除され削除ボタンを表示。表示ON/OFF・長さ変更・差し替えが可能 |
