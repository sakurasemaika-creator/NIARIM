# 06_保存・共有

## 保存の分類

```
保存
├─ アニメ保存（動画書き出し）
│
└─ プロジェクト保存
    ├─ 自動保存（Autosave）
    └─ 手動保存
         ├─ セーブスロット方式
         └─ セーブツリー方式
```

---

## ファイル形式

| 形式 | 用途 |
|------|------|
| .niapro | 通常プロジェクト保存（編集用） |
| .niashare | 共有用（複製してプロジェクトへ追加） |
| .niatra | 引き継ぎ用（旧称 .stutra） |
| MP4 | 動画書き出し |
| GIF | 書き出し時のみ（GIFモードは存在しない） |
| 透過WebM | 動画書き出し（アルファチャンネル保持） |
| .niatheme | UIテーマ共有用 |

## 動画書き出しエンコーダー（ライセンス・特許対応）

- **MP4（H.264）**：Android標準のハードウェアエンコーダー（MediaCodec、
  `android/app`側のネイティブ実装`HardwareVideoEncoder.kt`）で生成する。
  FFmpeg/libx264（GPLライセンス）は使用しない。理由は2点：
  1. libx264はGPLのため、アプリへ組み込んで配布するとコピーレフト
     （対応ソースコード開示義務等）への対応が必要になる
  2. アプリが自前のソフトウェアエンコーダーでH.264を生成する場合、
     H.264規格自体の特許ロイヤリティ（Via Licensing Allianceが管理する
     AVC特許プール）の当事者になり得る。ハードウェアエンコーダーは
     端末メーカー・OSベンダー側で特許処理済みという前提に乗れるため、
     アプリ側の特許論点を回避できる
- **透過WebM（VP9）**：引き続きFFmpeg（`ffmpeg_kit_flutter_new_video`、
  GPLコーデックを含まないLGPL 3.0版）を使用する。VP9自体がロイヤリティ
  フリーであり、libvpxもBSDライセンスのため問題がない。

（経緯）この対応は一度、実機（Android 16）での起動時クラッシュを疑われ
全面revertされたが、後の調査でクラッシュの真因はリリースビルドのR8
（コード圧縮・難読化）であり、本対応自体は無関係だったことが判明した
ため再適用した。R8は現時点で無効化されたままのため、R8再有効化時は
再度実機での慎重な検証が必要（詳細は12_実装チェックリスト.mdの追記を
参照）。
- 無料版のエンドカード（NIARIMロゴ、約5秒）は、本編動画への後結合
  ではなく、フレーム生成の段階でフレーム列の末尾へ追加してから
  一括エンコードする（`dart:ui`のテキスト描画で都度生成。FFmpegの
  drawtext/concatフィルターには依存しない）。

## 自動保存（Autosave）

- 描画などで変更が発生したタイミングで自動保存
- クラッシュ・ファイル破損時の復元専用
- 最大3件固定・古い順に自動削除
- Undo履歴とは別管理
- 手動保存（セーブスロット・セーブツリー）とは完全に独立

---

## 手動保存

### 保存方式

設定から保存方式を選択できる。

| 方式 | 内容 |
|------|------|
| セーブスロット方式 | 固定数のスロットに保存。スロット数は設定から変更可能 |
| セーブツリー方式 | 保存データを履歴（ツリー）形式で管理。保存数に制限なし |

### セーブスロット方式

| 品質 | 最大件数 |
|------|---------|
| 低品質 | 5件 |
| 中品質 | 10件 |

- 保存先スロットはユーザーが選択する（自動上書きしない）
- 各スロットにサムネイル・保存日時・任意のセーブ名を表示

### セーブツリー方式（高品質）

- 保存数無制限
- 任意でセーブ名を付けられる
- 過去のセーブ地点へ戻って保存すると枝分かれする
- 元の最新セーブは消えない

詳細は 23_セーブツリー仕様.md を参照。

### 保存方式変更・スロット数変更

以下の場合は保存データ変更画面を表示する。

- セーブツリー → セーブスロット
- セーブスロット数を減らす
- 保存データ数が変更後の保存上限を超える

スロット数を増やす場合は表示しない。

詳細は 23_セーブツリー仕様.md を参照。

## 保存プリセット

保存プリセットは品質・保存方式・その他保存設定をまとめて保持するプリセット。

- ブラシプリセット・自動塗りプリセット・UIテーマプリセットとは完全独立

### 保存設定画面の流れ

```
品質設定
↓
端末スペック別おすすめ
  ・低品質
  ・中品質
  ・高品質
↓
プリセット自動適用

または

品質設定
↓
カスタム
↓
保存方式
↓
各詳細設定
```

デフォルトはプリセット表示。「カスタム」をタップするとアコーディオン展開で詳細設定が表示される。

---

## Undo

- デフォルト50回
- 設定変更可
- プロジェクト保存時に保存しない
- 自動保存とは独立

## 共有フロー（.niashare）

```
.niashare作成
↓
端末に保存
↓
受信側がタップ → NIARIMで開く
↓
確認ダイアログ
「この共有ファイルを複製して通常プロジェクトとして保存しますか？」
↓
プロジェクトタブへ追加
（.niashare自体は変更されない）
```

## 引き継ぎ（.niatra）

引き継ぐ項目をチェックボックスで選択できる。

```
☑ 設定
☑ 素材
☑ ブラシ
☑ プリセット
☑ UIテーマ

[全選択]  [全解除]
```

## ゴミ箱

- 削除したプロジェクトはゴミ箱タブへ移動
- ゴミ箱一覧でサムネイル・削除日時を表示
- 復元：元の場所へ戻す
- 完全削除：確認ダイアログを表示してから削除

```
完全に削除しますか？
元に戻すことはできません。

[キャンセル]  [削除]
```

- 自動削除設定：OFF / 30日 / 60日 / 90日（設定画面で変更可能）

## 書き出し後フロー

```
書き出し完了
↓
・共有（写真アプリ等の保存先を選んで保存・写真アプリ等で開く）
・プロジェクト一覧へ戻る
・キャンバスへ戻る
```

- 書き出し結果（MP4/GIF/WebM）はアプリの永続領域（`exports`フォルダ）に
  保存される。完了ダイアログにファイル名を表示し、端末の「写真」アプリ
  等で見つけたい場合は「共有」から保存先アプリを選ぶ運用とする
  （`share_plus`のOS共有シート経由。候補に写真/ギャラリーアプリが
  表示されるため、独自のACTION_VIEW実装は不要）
- 処理中はキャンセルボタンを表示する（フレーム生成中は即座に中断、
  最終エンコード中にキャンセルした場合は処理完了後に出力を破棄する）

### 作品一覧タブ

ホーム画面に「作品一覧」タブを設け、`exports`フォルダ内の書き出し済み
ファイル（MP4/GIF/WebM）を更新日時の新しい順で一覧表示する。

- 各項目：ファイル名・更新日時・サイズを表示
- タップ：アプリ内プレビュー（MP4/WebMは`video_player`、GIFは
  `Image.file`のアニメーション再生）
- 共有ボタン：書き出し完了ダイアログと同じ`share_plus`の共有シートで
  写真アプリ等へ「開く」
- 削除ボタン：確認ダイアログの上でファイルを削除（永続化により
  増え続けるファイルをユーザー自身が管理できるようにする）
- 引っ張って更新：`RefreshIndicator`でファイル一覧を再取得

## EndCard Track（エンドロゴ）

動画書き出し時、本編終了後にNIARIMロゴ動画（約5秒）を自動追加する。

```
ユーザー作品（本編）
↓
本編終了
↓
NIARIMロゴ動画（約5秒）
↓
動画終了
```

- 本編アニメーション部分には一切表示しない
- 内部的にEndCard Trackとして管理

| 版 | 状態 |
|----|------|
| 無料版 | タイムライン上に南京錠付きで表示。タップするとPremium誘導ダイアログを表示。削除・移動・編集・操作不可 |
| プレミアム | 南京錠が解除され削除ボタンを表示。表示ON/OFF・長さ変更・差し替えが可能 |
