# 23\_セーブツリー仕様

## 概要

セーブツリーはプロジェクトの手動保存履歴を管理する機能。自動保存とは完全に独立している。プロジェクト詳細画面・タイムラインモードの三点メニューからアクセスできる。

---

## アクセス方法

- プロジェクト詳細画面 → セーブツリーボタン
- タイムラインモード → 三点メニュー（⋮）→ セーブツリー

---

## 品質設定との連携

| 品質     | 方式                                          | スロット数     |
| -------- | --------------------------------------------- | -------------- |
| 低品質   | スロット方式                                  | 5スロット固定  |
| 中品質   | スロット方式                                  | 10スロット固定 |
| 高品質   | ツリー方式                                    | 制限なし       |
| カスタム | スロット方式（任意件数）/ ツリー方式 から選択 |

---

## 保存方式変更・スロット数変更

保存方式変更と保存可能数変更は別UI・別イベントで処理する。

- 保存方式変更：`_onCustomSaveModeChanged()` で処理
- 保存可能数変更：`_onCustomSlotCountChanged()` で処理

保存方式変更時に保存可能数は変更されないため、PerformanceServiceとSaveTreeServiceのスロット数が不一致になることはない。

保存方式または保存可能数がユーザーに影響する場合のみ、保存データ変更画面を表示する。

### 変更画面を表示する場合

- セーブツリー → セーブスロット
- セーブスロット → セーブツリー
- セーブスロット数を減らす（例：5件→スロット3件、スロット10件→スロット5件）
- 保存データ数が変更後の保存上限を超える

### 変更画面を表示しない場合

- スロット数を増やす（例：3件→スロット5件、スロット5件→スロット10件）
- 保存方式・保存可能数に変更がない（例：スロット3件→スロット3件、ツリー→ツリー）

保存可能数が増える場合や変更なしの場合は、そのまま設定を変更し保存データ変更画面は表示しない。

### 保存データ変更画面

```
保存方式（または保存数）が変更されます。

現在の保存データ数が
新しい保存可能数を超えています。

保持する保存データを選択してください。

保持できる保存数：○件

────────────────

【最新○件を保存】

【保存データを選択】

【キャンセル】
```

#### 最新○件を保存

更新日時順で最新○件を自動選択する。その後「選択されなかった保存データ」画面へ進む。

#### 保存データを選択

現在使用している保存方式と同じ画面レイアウトで保存データを選択する。

- 現在がセーブツリー方式の場合：セーブツリー画面を複数選択モードで表示
- 現在がセーブスロット方式の場合：セーブスロット画面を複数選択モードで表示

新しい画面は作らず、普段使っている保存画面をそのまま利用する。

### 保存データ選択の動作

- 保存データをタップすると選択状態になる
- 選択上限は変更後の保存数まで
- 上限到達時：残りの保存データはグレーアウト＋タップ不可になる（トースト表示なし）
- 選択済みデータを再度タップすると選択解除され、グレーアウトも自動解除される

### 選択されなかった保存データ

```
選択されなかった保存データ

○ アーカイブとして保持する（推奨）
  セーブツリー方式へ戻したときに自動で復元されます。
  ストレージ容量を使用します。

○ 完全に削除する
  選択されなかった保存データを完全に削除します。
  ストレージ容量を節約できます。
  ※削除したデータは元に戻せません。

[戻る]  [変更する]
```

---

## アーカイブ

- アーカイブされた保存データは通常は表示しない
- **セーブスロット方式からセーブツリー方式へ変更した場合のみ**、自動で保存一覧へ復元する
- ツリー方式からツリー方式への変更時は復元しない
- ユーザーがアーカイブを管理する必要はない

---

## 保存方式変更例

### セーブツリー → 3スロット

```
Save1 / Save2 / Save3 / Save4 / Save5 / Save6
↓
保持する3件を選択
↓
Slot1 → Save6 / Slot2 → Save4 / Slot3 → Save2
↓
残りはアーカイブ or 削除を選択
```

### 6スロット → 3スロット

```
Slot1 / Slot2 / Slot3 / Slot4 / Slot5 / Slot6
↓
保持する3件を選択
↓
Slot1 / Slot3 / Slot6
↓
残りはアーカイブ or 削除を選択
```

---

## 設計方針

- 保存方式変更時も普段見慣れた画面（セーブツリー／セーブスロット）で選択できるため学習コストがない
- 保存データは勝手に削除せず、アーカイブを推奨する
- 保存上限に達したら未選択データはグレーアウト＋タップ無効にし、エラーメッセージに頼らず直感的に上限を伝える
- 容量を節約したいユーザー向けに「完全削除」も選択可能にする

---

## スロット方式（低品質・中品質）

- 手動保存するたびに空きスロットへ記録
- スロットは自動で上書きされない。ユーザーが任意のスロットを選んで保存・削除する
- 各スロットに保存日時・サムネイル・コメントを表示
- スロットをタップして選択 → 復元

```
スロット1  2024/01/15 14:32  [サムネイル]  「背景完成」
スロット2  2024/01/15 15:10  [サムネイル]  「人物追加」
スロット3  2024/01/15 16:45  [サムネイル]  ← 現在
```

---

## ツリー方式（高品質・カスタム）

- 手動保存のたびに分岐を作成し、ツリー状に履歴を管理
- 任意の分岐点へ戻って別の方向へ編集を進められる
- 各ノードに保存日時・サムネイル・コメントを表示
- コメントはGitのコミットメッセージのように保存内容を記録できる
- ノードをタップして選択 → 復元

```
[保存1：「初期状態」]
  └─[保存2：「背景完成」]
      ├─[保存3：「人物追加」] ← 現在
      └─[保存4：「別パターン試作」]
```

---

## 共通操作

| 操作           | 内容                                     |
| -------------- | ---------------------------------------- |
| 保存           | 現在の状態を新しいスロット・ノードへ記録 |
| 復元           | 選択したスロット・ノードの状態へ戻す     |
| 削除           | 選択したスロット・ノードを削除           |
| コメント入力   | 保存時に任意のコメントを入力できる       |
| サムネイル表示 | 各スロット・ノードにサムネイルを表示     |

---

## 自動保存との関係

自動保存とセーブツリーは完全に独立している。

| 項目         | 自動保存                                     | セーブツリー（手動保存）         |
| ------------ | -------------------------------------------- | -------------------------------- |
| トリガー     | キャンバスの内容を変える操作のたびに自動実行 | ユーザーが手動で保存             |
| 目的         | クラッシュ時の復元                           | 任意の状態への巻き戻し・分岐管理 |
| 保存数       | 最大3件（古い順で削除）                      | 品質設定に依存                   |
| ユーザー操作 | 不要                                         | 必要                             |

---

## 保存データの管理

- セーブツリーのデータはプロジェクト内の `SaveTree/` フォルダで管理
- アーカイブデータは `SaveTree/Archive/` フォルダで管理
- 自動保存データはプロジェクト内の `Autosave/` フォルダで管理（別フォルダ）
- 容量が大きくなる場合はユーザーへ通知
