# 30. AI用：自律動作確認（実操作＋スクショ）の手順

このリポジトリには実機（Androidの実端末）が無い。にもかかわらず「意図どおり
動くか」を確かめる必要があるため、**本番の画面をそのままテストへ載せ、AI自身が
実タップ・実ドラッグで操作し、各段階をPNGへ焼いて目視する**という手順を使う。

このファイルは、Claude Code以外のモデル／別セッションでも同じことが再現できる
ように、そのまま貼って使えるプロンプトと、必ず踏む落とし穴をまとめたもの。

---

## そのまま渡せるプロンプト

> このFlutterリポジトリには実機がありません。次の手順で「実際に操作して
> スクリーンショットを撮り、意図どおりの画面になっているか自分の目で確認する」
> 検証をしてください。テストが緑になったことを結論にせず、**焼いたPNGを1枚ずつ
> 実際に見て**判断してください。
>
> 1. 検証したい機能について「ユーザーが実際に行う操作の並び」を書き出す。
>    （例：ペンで線を描く → 選択ツールへ切替 → 範囲を囲む → 回転させる →
>    全解除する → ツールを抜ける）
> 2. `test/` に操作ウォークスルーのテストを1本作る。ダミーのウィジェットでは
>    なく、**本番の画面ウィジェットをそのまま**載せること。プロバイダは
>    `app_bootstrap.dart` の `buildAppProviders()` を使う（非同期なので
>    `tester.runAsync` の中で呼ぶ）。
> 3. `MaterialApp` には必ず `theme:`（`context.watch<ThemeService>().themeData`）と
>    ロケール、`AppLocalizations.localizationsDelegates` を渡す。
>    `test/helpers/load_app_fonts.dart` の `loadAppFonts(tester)` を最初に呼ぶ。
>    これを忘れると **本番と違う配色・豆腐（□）の画面**を撮って
>    「問題なし」と誤判定する。
> 4. 操作の各段階で `RepaintBoundary` を `toImage()` → PNG保存する。
>    保存先は `build/<機能名>-walkthrough/` に `00_xxx.png` から連番で。
> 5. 焼いたPNGを**全部**開いて見る。期待とズレていたら、テストのコードでは
>    なく**実装を疑う**こと（テストは緑のままズレていることが多い）。
> 6. 見つけた不具合は直し、その不具合を捉える回帰テストを足す。足したテストは
>    **修正を元に戻すと落ちること**を必ず確認する（両方で通るテストは無意味）。
> 7. 最後に `dart format lib test tool` → `flutter analyze`（0 issues）→
>    `flutter test`（全成功）を通してからコミットする。

## 必ず踏む落とし穴（ここを知らないと必ずハマる）

### 1. 本物の非同期は `tester.pump()` では進まない

`flutter_test` は既定でFakeAsync（偽装時間）の下で走る。次の処理は
`tester.pump(Duration)` を何回回しても**完了しない**。

- `picture.toImage()` / `compositeLayerToImage()` / `toByteData()`
- `ui.decodeImageFromPixels()` のコールバック
- PNGエンコード、`File` の読み書き

症状は「何も起きない」か「タイムアウトでハング」。待つ側は必ずこうする。

```dart
Future<void> settle([int rounds = 10]) async {
  for (var i = 0; i < rounds; i++) {
    await tester.runAsync(
      () => Future<void>.delayed(const Duration(milliseconds: 50)),
    );
    await tester.pump(const Duration(milliseconds: 50));
  }
}
```

ジェスチャー自体は `runAsync` の**外**で駆動する（`runAsync` はネストできない）。
ストロークの実画素化も本物の非同期なので、**1点動かすごとに**実時間を進めないと
最初の点しか描かれない（＝線ではなく点1つのPNGが撮れる）。

### 2. ドラッグ位置は「ウィジェットの割合」で決めない

描画エリアはウィジェットの中央へアスペクト比フィットで置かれる。割合で指定すると
狙った位置からずれ、拡大縮小率や回転角も計算どおりにならない。**プロジェクトの
ピクセル座標**から毎回変換すること。

```dart
Offset at(double x, double y) {
  final rect = tester.getRect(find.byType(CanvasArea));
  final scale = math.min(rect.width / exportW, rect.height / exportH);
  final origin = Offset(
    rect.left + (rect.width - exportW * scale) / 2,
    rect.top + (rect.height - exportH * scale) / 2,
  );
  return origin + Offset(x * scale, y * scale);
}
```

さらに、**操作によってレイアウトが変わる**（例：選択ツールへ入るとツールバーと
フレーム一覧が畳まれてキャンバスが縦に広がる）。矩形を一度キャッシュすると
畳まれた後にずれるので、**呼ぶたびに取り直す**こと。

### 3. アニメーションが終わる前に撮ると別物が写る

ポップアップメニューの入場・退場、テーマ切替、ボトムシートの退場には
数百msかかる。撮る前に十分 `pump` すること。実際に

- メニューの最後の項目がまだフェードインしておらず「項目が足りない」PNG
- 閉じかけのメニューが被って肝心の画面が見えないPNG
- 開いたパネルの上に設定シートが乗ったままのPNG

を撮って誤判定しかけた。判定は**PNGではなくアサーション**で行い、PNGは
「人間が見て気付くための材料」と割り切ると安全。

### 4. 狭い画面ではボタンが画面外にいる

ツールバーは横スクロール、設定シートは縦スクロール。座標が表示領域の外だと
タップはヒットテストに当たらず、**例外も出ないまま「押したのに何も起きない」**
形の失敗になる。`tester.ensureVisible(finder)` を挟むこと。

### 5. 初回タップの吹き出しが操作を吸う

`FirstUseTooltip` は表示中に画面全体の透明バリアを敷く。素の状態だと
「あるボタンを押す→吹き出しが出る→次の操作がバリアに吸われて何も起きない」
になる。ウォークスルーでは全キーを表示済みにしておく。

```dart
SharedPreferences.setMockInitialValues({
  firstUseTooltipsSeenKey: kAllFirstUseTooltipKeys,
});
```

### 6. `path_provider` は未登録

ディスクI/Oを伴う画面は `MethodChannel('plugins.flutter.io/path_provider')` を
モックしてから載せる。

### 7. 縮小表示でPNGを見ると細い文字が沈んで見える

低解像度で焼いたPNGをそのまま眺めると、細い明朝体の文字が背景に溶けて
「コントラスト不足の不具合だ」と誤読しやすい。怪しいと思ったら
**画素値を測る**か、`Image.NEAREST` で3倍程度に拡大して確認すること
（実際にこれで「不具合ではなかった」ケースがあった）。

## この方法で実際に見つかった不具合

- **SnackBarの文字がアプリ全体で端末標準フォントだった**：
  `snackBarTheme.contentTextStyle` へ素の `TextStyle()` を渡していたため
  `ThemeData.fontFamily` を継承していなかった。テストではフォントが
  読み込まれず豆腐（□）になったので気付けた。
- **「全選択」を押しても何も起きなかった**：トークン方式の通知がビルド中に
  親の `setState` を呼んで例外になり、通知が届いていなかった。
- **FilledButtonのラベルが端末標準フォント**／**ジェスチャー選択シートが
  77pxオーバーフロー**：ダイアログを開いた状態のPNG監査で発覚。
- **作品広場の最終行のカードがFABに永久に隠れていた**：ルート監査のPNGで発覚。

いずれも**テストは緑のまま**だった。PNGを見なければ気付けなかった種類の
不具合であることに注意。
