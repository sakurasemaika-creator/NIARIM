# タイムライン編集操作仕様

この文書は、タイムライン上の素材編集を「長さ調整」「画面トリミング」「分割」「切り取り」に分離し、操作名・対象・保存データ・書き出し時の扱いを統一するための仕様である。

## 1. 機能名と責務

| UI名 | 英語名 | 目的 | 対象 |
|---|---|---|---|
| 長さ調整 | Duration / Speed | タイムライン上の時間範囲と再生速度を変更する | 音声・動画・画像・テキスト・読み上げ・カメラ／キーフレーム |
| 画面トリミング | Crop | 素材の見た目の表示領域を切り抜く | 画像・動画 |
| 範囲選択 | Region Edit | 素材の絵の一部を選び、移動・変形・複製・削除する | 画像・動画 |
| 分割 | Split | クリップを再生ヘッド位置で前後2つに分ける | 分割対応の全タイムライン素材 |
| 切り取り | Cut to Clipboard | 素材を一時クリップボードへ移し、貼り付け可能にする | 選択したクリップ |

「カット」はUI上の機能名として使用しない。前後の不要区間を詰める操作は「長さ調整」、クリップを二分する操作は「分割」、クリップボードへ移す操作は「切り取り」と呼ぶ。

## 2. 長さ調整

### 2.1 時間範囲
- クリップのタイムライン上の開始位置・終了位置を変更する。
- 左右の端ハンドルと数値入力の両方で指定できる。
- 動画・音声では素材内の使用開始／終了位置を保持し、画像・テキストではタイムライン上の表示期間を変更する。
- 元ファイルや元画像の画素データを破壊しない。
- 既存のドラッグによる開始位置移動・端ハンドルによる範囲変更は維持し、パネル内の名称を「長さ調整」に統一する。
- 実装（2026-11-25）：素材（テキスト・画像・動画）の編集パネルの「長さ調整」の欄と、音声・読み上げのシートの「長さ調整」に「時間範囲」を置く。開始フレーム・終了フレームを数字で入れ（タイムラインと同じ1から数える番号）、Enterか欄を離れたときに確定する（入力途中の値は使わない）。開始を変えると終了はそのまま、終了を変えると開始はそのまま（端のドラッグと同じ）。シーンの外・開始が終了より後・数字でない値は確定せず理由を出し、同じ列の別のクリップと重なる範囲は変えずに知らせる。音声は開始を動かすと音の中の再生位置も同じだけずれ（タイミングを保つ）、音の先頭より前には広げない。動画は使用範囲を保つ（長くした分は最後の使用フレームを保持）。素材の変更は1回のUndo、音声はシートの「キャンセル」で元に戻る。長さ（フレーム数と秒）を表示する。

### 2.2 再生速度
- 速度は倍率で保持する。1.0xが通常速度、2.0xが2倍速、0.5xが半分の速度。
- スライダーと数値入力を必ず両方用意する。スライダーは低倍率域を細かく操作できる目盛り設計とし、数値入力では任意の小数を指定できる。
- 通常操作域は0.1x〜16x、拡張入力域は0.01x〜100xを初期案とする。100xは上限値として許可し、端末性能を理由に一律で拒否しない。
- 0より大きい有限値のみ許可する。NaN、Infinity、0、負数は拒否する。小数の丸めは保存時に不用意に行わない。
- 速度変更は非破壊編集とし、元素材のファイルや元のキーフレーム値を上書きしない。
- 速度変更後の表示長は、元の対象時間 ÷ 速度倍率で求める。フレーム単位へ丸める際は、最短1フレームを保証し、隣接クリップとの重なり・意図しない空白を作らない。
- 速度変更後も、音声・映像・読み上げの同期を保つ。音声と映像を連動させるか、片方だけ速度変更するかを明示的に選べるようにする。
- 100x付近では音声の聞き取りやすさは保証しない。音声をミュートする選択肢を用意し、音声処理は映像と独立して扱う。
- プレビュー再生はフレームを飛ばして追従してよいが、タイムライン上の時間・書き出し結果は正確な倍率を保つ。
- 書き出しはリアルタイム処理を要求しない。処理に時間がかかる場合は進捗を表示し、キャンセル可能にする。処理時間の長さを理由に倍率を下げない。

### 2.3 対象ごとの速度の意味
- **動画**：素材内の再生時刻を倍率で進める。音声を含む動画は映像と音声の速度を同期させる設定を持つ。
- **音声**：音声の再生速度を変更する。ピッチ維持のON/OFFを選べる。極端な高速では音質・聞き取りやすさが低下することを許容事項として明示する。
- **読み上げ**：生成済み音声クリップの速度を変更する。読み上げテキスト自体の再生成を必須にしない。
- **画像・テキスト**：静止素材そのものに再生速度はないため、速度欄は表示せず、開始・終了位置による表示期間の変更だけを行う。
- **レイヤーキーフレーム**：対象素材のキーフレーム時刻を非破壊でリタイムする。キーフレームの値・補間カーブは維持し、時間間隔だけを倍率に応じて変える。画像・テキスト素材でもキーフレームがある場合は、そのアニメーションに速度を適用できる。
- **カメラキーフレーム**：選択したカメラアニメーション範囲をリタイムする。カメラの位置・ズーム・回転値と補間結果を維持する。対象範囲外のキーフレームは変更しない。
- **キーフレーム範囲の選択**：単一キーだけでなく、範囲選択した複数キーを一括リタイムできる。範囲外のキーとの衝突時は、適用前にプレビューし、確定できない配置は拒否する。

### 2.4 速度UI
- 「長さ調整」パネル内に「時間範囲」「速度」の項目を分ける。（実装済み：動画の速度は素材の編集パネルの「長さ調整」へ移し、「動画」の欄は音量と使用範囲だけにした。音声・読み上げのシートも「長さ調整」の見出しの下に時間範囲・速度を置く。画像・テキストは時間範囲だけ。）
- 速度欄は倍率表記（例：1.00x）とし、スライダーと直接入力を同期させる。
- 代表値のクイック選択：0.25x / 0.5x / 1x / 2x / 4x / 8x / 16x / 100x。
- 数値入力は小数を許可し、入力途中の不完全値を即時保存しない。確定時に範囲検証する。
- 速度変更によりクリップの終了位置が変わる場合、変更前後の終了位置をプレビューする。既存素材と重なる場合は、勝手に上書き・削除せず、適用を保留してユーザーへ知らせる。

## 3. 画面トリミング
- 画像・動画の見た目の領域を切り抜く機能。時間範囲の変更とは独立させる。
- 元ファイル・元画像の画素は変更せず、クロップ矩形を素材の編集情報として保存する。
- プレビュー上のハンドル操作と数値入力を用意する。
- 位置・拡大・回転・マスクとは別の編集値として保持し、編集順によって結果が変わらない座標系を定義する。
- 動画では全フレームに同じクロップを適用する。時間変化するクロップは別機能として扱い、初期実装には含めない。

### 3.1 範囲選択（2026-11-25、所有者の依頼「画像、動画などの見た目に関係する素材はトリミングだけでなく範囲選択(変形、移動、複製、削除など)もできるようにしてください」）
- 画像・動画の素材の編集パネルに「範囲選択」の欄を置く。欄を開いている間、プレビューのつまみは範囲選択のものに替わる（欄を閉じる・他の欄へ移ると素材の配置のつまみへ戻る）。
- 範囲の形は「四角」「楕円」「自由な形」。プレビューの上をドラッグして囲む。四角・楕円は8つの丸で大きさを変え、内側をドラッグして範囲を動かし、外側をタップすると選択を解除する。「全体を選ぶ」で素材の描かれた部分（トリミングの内側）を選ぶ。選んでいるだけでは素材を変えない（取り消しの記録も作らない）。
- 選んだ範囲に対して「移動・変形」（その部分を抜き出して透明にし、動かし・大きさ・縦横の伸縮・回転・左右／上下反転して置き直す）、「複製」（元を残し、写しを少しずらして置く）、「削除」（その部分を透明にする）を選ぶ。移動・変形と複製は、選んだ直後からプレビューで動かせる（どこをドラッグしても移動、角の丸で縦横そろえて拡大縮小、辺の丸で縦か横に伸縮、上の丸で回転、2本指で移動・拡大縮小・回転）。パネルのスライダー（X・Y移動、横・縦の大きさ、回転）と反転・元の位置に戻すボタンでも変えられる。小さく写っている範囲では、辺の丸は角の丸とつかみ分けられないので出さない。
- 編集は素材のレイヤーに順番に持つ（`Layer.regionEdits`、`LayerRegionEdit`）。各編集は「範囲（素材のレイヤーの幅・高さに対する0〜1の割合。自由な形は点の列）・種類・中心の移動（割合）・横縦の倍率（負は反転）・回転（度、時計回り）」。元の画像・動画のファイルは変えない。
- 編集はトリミングの後、素材の配置（位置・拡大・回転・X/Y軸回転）・マスク・合成モード・クリッピングの前に、順番に描く。トリミングの外へ動かした部分も見える。動画はどのコマにも同じ編集をかける。
- 一覧（「範囲の編集（件数）」）で編集を1つずつ外す・すべて外す。移動・変形と複製の行を押すと、その部分のつまみに戻って変え直せる。1つの素材の編集は24個まで（どのコマでも順番に描くため）。
- 選ぶ・つまみ・スライダーの操作はそれぞれ1回の取り消しで戻る（ドラッグ1回で1手）。

## 4. 分割
- 分割モードへ入り、再生ヘッドを合わせて「適用」で確定する。キャンセルで何も変更しない。
- 分割位置をまたぐクリップのみ対象にする。先頭・末尾と同じ位置では分割しない。
- 選択中シーンの分割対象クリップを対象とし、分割後は前後の2クリップが同じ素材内容・トラック行・表示順を維持する。
- 動画・音声は素材内の再生位置、速度、音量、ピッチ設定を引き継ぐ。
- フェードインは前半、フェードアウトは後半へ保持する。分割点に意図しないフェードを追加しない。
- 画像・テキスト・動画はマスク、クロップ、配置、キーフレーム、重なり順などの編集情報を複製する。キーフレーム時刻は前後クリップのローカル時間に合わせて整合させる。
- Undo/Redoで分割全体を1操作として戻せる。

## 5. 切り取り（クリップボード）
- 選択したクリップを一時クリップボードへ保持し、元位置から削除する。
- コピーと切り取りを区別し、貼り付け時は現在の再生ヘッド位置を基準に配置する。
- クリップボードには素材参照だけでなく、速度・時間範囲・クロップ・マスク・配置・キーフレーム・音量・フェード等の編集情報を含める。
- クリップボード内容が失われても元素材ファイル自体を削除しない。
- Undo/Redoは切り取り・貼り付けをそれぞれ1操作として扱う。
- 現状（2026-11-25）：タイムラインの切り取りは、シーン・フレーム・クリップとも「印を付け、貼り付けたときに元を消す（移動）」既存の作りで、貼り付け（移動）が1回のUndo。切り取った時点で元を消す作りへ変えるかは所有者の判断待ち。速度・端数・クロップ・範囲選択・マスク・配置・キーフレーム・音量・フェードは貼り付け・複製で引き継ぐ（`test/timeline_clip_edits_kept_test.dart`）。

## 6. 保存・互換性・検証
- 新しい速度・クロップ情報は既存プロジェクトを壊さない任意フィールドとして保存し、未設定の古いデータは速度1.0x・クロップなしとして読み込む。
- 範囲選択の編集（`regionEdits`）も任意フィールド。無ければ編集なし、読めない1件（範囲の外・小さすぎる範囲・未知の種類・数でない値・同じID）はその1件だけを外して読み、24件を超える分は読まない。
- 速度変更、分割、クロップ、切り取りの各操作はUndo/Redo・自動保存・プロジェクト複製・書き出しで一貫させる。
- 動画・音声の書き出しではタイムスタンプを倍率に合わせて変換し、映像と音声の同期をテストする。
- テスト対象：0.1x、0.5x、1x、2x、16x、100x、端数倍率、1フレーム未満の結果、クリップ境界、複数キーの衝突、旧プロジェクト読み込み、Undo/Redo、キャンセル。
- 画質補間を行わない高速化では、元映像に存在しないフレームは生成しない。スロー再生でフレーム数が不足する場合は、フレーム補間を別の品質オプションとして扱う。

## 7. プレビューと書き出しの一致（必須要件）

プレビューは書き出し結果の簡易版・別実装にせず、**同じ編集データと同じ描画／音声処理ルールから結果を生成する**。ユーザーがプレビューで確認した見た目・音声が、書き出しで別の表現に変わらないことを最優先とする。

### 7.1 映像・画面表示
- プレビューと書き出しは共通のタイムライン評価処理を使用する。素材の表示時刻、速度、クロップ、位置・拡大・回転、マスク、不透明度、合成順、ブレンドモード、エフェクト、カメラ変形、キーフレーム値・補間を同じ規則で評価する。
- 同じプロジェクト状態・同じタイムスタンプ・同じ出力設定なら、プレビューで表示されるフレームと書き出しフレームの構図・色・合成結果が一致すること。GPU／CPUなど実行経路の違いによる微小な数値誤差は許容範囲を定義してテストするが、見た目に分かる差は許容しない。
- プレビューの負荷が高い場合、画面更新のフレーム落ちや一時的な遅延は許容する。ただし、タイムライン時刻の評価を飛ばして誤ったフレームを表示したり、速度・補間・エフェクトを省略したりしてはならない。再生停止・シーク後は指定時刻の正しいフレームを表示する。
- 低解像度プロキシや軽量プレビューを将来導入する場合も、明示的なプレビュー品質設定として分離する。標準プレビューは書き出しと同じ解像度・色処理・エフェクト設定を基準にする。プロキシ使用中は品質差があることを明確に表示し、最終確認用の高品質プレビューを提供する。
- 書き出し設定（解像度、フレームレート、アスペクト比、色空間等）がプレビューと異なる場合は、プレビュー側も同じ設定に切り替えて確認できるようにする。設定差を黙って適用しない。

### 7.2 音声
- プレビューと書き出しは共通の音声タイムライン評価ルールを使用する。クリップ開始／終了、素材内オフセット、速度、ピッチ維持設定、音量、フェード、ミュート、トラック音量、パン、ミキシング順、読み上げ音声の扱いを一致させる。
- プレビュー再生と書き出しで、同じタイムスタンプにおける音声内容・速度・音量バランス・フェード結果が一致すること。出力サンプルレートやコーデックによる差は別途定義し、意図しない音量変化・クリップ・無音区間・同期ずれを発生させない。
- 動画内音声、独立音声、読み上げ音声、BGM／効果音を同じマスタータイムラインで同期する。速度変更・分割・長さ調整後も映像との同期を維持する。
- 動画内音声は**使用範囲だけ**鳴る（2026-11-25）：素材の使用開始（端数を含む）から使用終了フレームの末尾までを、音の速度（「音も同じ速度にする」がオンなら動画の速度、オフなら1x）で読む。クリップがそれより長く、映像が最後の使用フレームを保持している所は無音。プレビューの再生・書き出しの音・動画の行の波形はすべてこの同じ範囲で止める（`TimelineVideoTimeMapper.soundingFrames`）。分割で後半が保持の所だけになったときは、後半の素材の開始を本来の位置（使用終了より後）のまま保存し、映像は最後の使用フレームを出し、音は無音にする（前半と後半の音の合計は分割前と同じ）。
- 100xなど極端な速度で音質が劣化する場合も、プレビューだけ別の速度処理に切り替えない。プレビューと書き出しで同じピッチ維持・音声変換方式を使用し、聞き取り品質の限界はユーザーに示す。
- プレビューのリアルタイム再生で端末負荷が限界に達した場合は、音声を勝手に間引いたり速度を変更したりせず、再生負荷・ドロップを通知する。停止後のシーク再生・短区間プレビューでは正確な音声を確認できるようにする。

### 7.3 実装原則
- タイムラインの時間評価、キーフレーム補間、映像合成、クロップ／変形、音声ミキシングをUI層や書き出し専用コードに重複実装しない。共通エンジンまたは共有可能な純粋関数へ集約し、プレビューと書き出し双方から呼び出す。
- プレビュー専用のリアルタイム出力アダプターと、書き出し専用のオフライン出力アダプターは分離してよい。ただし、両者が使う時間評価・映像処理・音声処理の意味論は共通にする。
- 乱数・時間依存エフェクトを使う場合は、同一タイムスタンプで同じ結果を再現できるシード／評価方式を定義する。
- 編集中にプロジェクトが更新された場合、プレビューと書き出しが異なる編集状態を参照しないよう、書き出し開始時点の編集スナップショットを固定する。

### 7.4 一致検証
- 同一プロジェクトから、複数のタイムスタンプ（先頭・中間・末尾・クリップ境界・キーフレーム位置・速度変更境界）を選び、プレビュー描画フレームと書き出しフレームを画像比較する。
- 比較はピクセル差・許容誤差に加え、クロップ範囲、合成順、位置、色、エフェクトの有無を検証する。
- 音声は同一区間をプレビュー用レンダリングと書き出し用レンダリングで生成し、波形差・ピーク／RMS音量・無音区間・開始終了時刻・映像との同期差を検証する。
- 通常速度だけでなく0.1x、0.5x、2x、16x、100x、ピッチ維持ON/OFF、フェード、複数音声トラック、動画内音声＋外部音声＋読み上げの組み合わせをテストする。
- プレビューと書き出しで差が検出された場合は、書き出し結果を正としてプレビューを黙って許容するのではなく、共通処理の不一致として不具合扱いにする。

## 8. プレビュー／書き出し一致性

現在実装の差異と共通エンジン化の手順は [27_プレビュー書き出し一致性監査.md](27_プレビュー書き出し一致性監査.md) を参照。プレビュー／書き出し一致は必須要件であり、差分テスト通過前に達成済みとして扱わない。
