# 13B クリエイターミッション・コイン報酬仕様（2026-11-04）

**13A（リワード広告・コイン）に追加する仕様。** 1円相当＝100コインは**価格設定の参考尺度**であり、換金・購入・譲渡可能な通貨ではない。広告報酬の初期値10コイン／SSV確認済み視聴1回は変更しない。ミッション報酬はリワード広告と同じNIARIM User IDのウォレットへ合算する予定。

## 目的・収益上の制約

- アプリ起動・ログイン・単なる待機・連続操作だけで自動報酬を付与しない。作品を描く、作品広場のNIARIM内の自然な創作実績が増える動機を作る。
- 無制限の日次ログイン報酬、動画視聴、YouTube高評価・再生数・チャンネル登録・コメント・シェアに連動するコイン報酬は採用しない。YouTube API ServicesポリシーはYouTubeの閲覧・高評価・チャンネル登録等への報酬を禁止する。YouTube指標に依存する既存の「総合／日・週・月ランキング」はコイン条件として利用しない。
- ミッション経由のコインには**広告収益が1円も付随しない場合がある**ため、「全コイン交換に広告収益の裏付けがあり、月額サブスク以上の純利益が必ず得られる」というモデルとは両立しない。これを広告視聴による発行済みコインだと偽装しない。ユーザー単位の無料報酬原資を予算化し、全体の継続率・作品数・有料転換・広告収益で**長期的な収益性を測る**。特典の交換価格だけで赤字保証なしとは言えない。
- v1は**達成ごとに生涯1回**。同じ作品の再公開や別の作品による再達成、削除・再登録、端末変更、Premium加入・退会でリセットしない。初期ミッション完了後に週次ミッション等を追加する場合は別バージョンと別予算が必要。
- 17件全部を達成した場合の理論上の合計は**5,930コイン（比較尺度で59.30円相当）**。ただし一部は高難度で達成保証なし。これはあくまで試験用の初期報酬案であり、**本番での発行はセキュリティ・規約・経済設計の確認が済むまで無効**。
- コイン獲得のために操作回数・投稿数・フォロー操作の競争を煽らない。子どもにも無理な長時間制作を要求しない配慮を行い、報酬を得ない利用にも制約を課さない。

## 制作時間の計測と不正対策

既存実装 `ProjectService` はキャンバス／タイムラインに居る間、**10秒単位**で制作時間を加算し、最後のタップ／スクラブなどから**1分無操作**で停止する。各 `Project.totalWorkSeconds` は端末内の編集時間表示用として今後も維持する。

しかし端末内値は編集可能で、タップの連打や改造クライアントで増やせるので**コイン付与の証拠としては採用しない**。

サーバー検証に必要な最低限の追加仕様：
1. サーバーが認証済みNIARIM IDに結びつけた短命のセッションIDと開始時刻を発行。キャンバス／タイムラインの**実データの変更確定**（ブラシ筆跡、レイヤー追加・変形・タイムラインの実変更、アニメフレーム編集等）を入力とする。再生・スクラブ・ホーム画面の閲覧や空のタップは報酬用の実制作操作として数えない。
2. 5～10分ごと、または編集画面を離れた時にだけ、セッションID・単調増加シーケンス・合算した検証候補秒数・実変更操作の集計数を送る。筆圧・座標・ブラシ軌跡・画像・音声・作品内容は送信しない。
3. サーバーは自身の時刻差・上限・シーケンスの単調増加・1アカウント同時セッション排他・一定時間無操作・日次上限・アプリ改ざん防止の信号（Play Integrity等）を組み合わせ、認めた秒数だけ1ユーザーの `verifiedEditSeconds` に加算する。サーバー時刻以上の制作時間を受け入れない。クライアント報告だけで実作業を完全証明できないため、異常値監査・不正時の保留は不可欠。
4. 計測失敗／オフライン中でも絵は描ける。ローカル表示の制作時間と、コイン審査用サーバー検証済み時間は異なる可能性があることをUIに説明。バックグラウンド時間は除外。保存済み古い `totalWorkSeconds` を無条件に移行・信用しない（継続利用者の公平な移行は別途検討）。
5. **v1ソースではこのサーバー制作時間検証は未実装。したがって制作時間ミッションは現状コイン付与不可。**

## 安価なDynamoDB保存と重複防止

既存の `niarim-table`（Provisioned・GSI増設なし）を使う。ユーザー単位の既存ウォレット `USER#{niarimUserId}/COIN_WALLET` に報酬を加算し、ミッション状態は**ユーザーごとに1行**：`USER#{niarimUserId}/MISSION_STATE_V1`。

状態の最小項目：

```json
{
  "itemType": "CREATOR_MISSIONS_V1",
  "claimedMask": 1024,
  "verifiedEditSeconds": 0,
  "totalMissionCoins": 50,
  "revision": 2,
  "firstQualifiedAt": {},
  "claimedAt": {"10": 1790000000}
}
```

- `claimedMask` の各ビットがミッション獲得済みかを表し、永久変わらないID・ビット番号・必要条件・報酬枚数はソースコードのカタログで復元する。表示名の7言語・達成表・必要個数等の重複保存を避ける。
- `claimedAt` はビット番号→エポック秒だけ。展示用の時刻文字列はクライアントで生成する。未獲得の候補時刻は `firstQualifiedAt` にだけ残す。動画IDのリストやユーザーデータを丸ごとミッション用に複製しない。
- `GET /me/missions` は**認証IDの既存USERアイテム＋MISSION_STATE_V1の2件だけ**を参照し、一覧全体を返す。ブックマーク・順位・複数作品の判定は利用者が個別に**達成確認を要求した時のみ**既存の作品・ランキングインデックスを読む。20ページ（1ページ25作品）の上限以上で検証できない大量投稿者は未判定として扱い、誤って不合格・払出しを確定しない。
- `POST /me/missions/claim` はサーバーで本人を再認証し、本人の作品・サーバー側ブックマーク・フォロワー数・NIARIM独自ランキングだけを参照する。端末から送った `achieved=true` や制作時間・ブックマーク数は一切信用しない。
- 1回目の有効な達成確認では48時間の保留を記録し、2回目も条件を満たす場合のみ進める。付与時は `TransactWriteItems` で、`claimedMask` と `revision` の条件付き更新＋同じユーザーのウォレット加算を**同時確定**。二重クリック・再送で二重加算しない。高度な複数アカウント不正、端末改ざん、モデレーション未対応のまま本番機能を有効化しない。
- 1ユーザーのミッション状態は通常小さい1アイテムで、17ミッションを獲得しても大きな画像・ログデータは保存しない。秒ごとのタイマー更新をDynamoDBへ送らず、作業の合計値だけ保持する。
- 同じGoogleアカウントは `googleSub` → NIARIM User IDの既存サーバーマッピングを用いて引き継ぐ。機種変更で獲得済みフラグ・コイン枚数はリセットしない。
- DynamoDBの無料枠は2026-11時点でProvisioned 25 RCU／25 WCU・25GB（条件あり）。**保存容量の小ささだけでは無料を保証できない**。頻繁な書き込み・Query・ネットワーク・Lambda・ログも費用およびスロットリングに影響する。AWSの費用通知を設定して実測する。
- 完了報酬が後から変更されたときに既に獲得したコインを再計算しない。既存IDの額は凍結し、追加報酬を変えたい場合は新しいミッションID／bitを採用する。

## UI案・未実装要件

作品広場に「ミッション」、報酬ページに「制作ミッション／作品広場ミッション」、1回限りの条件と必要コイン枚数ではなく**付与コイン枚数**、未達成・達成確認待ち・保留中・獲得済みの表示を設ける。過度な長時間利用を促す通知は行わない。テーマ・外観のカラーを全UIに使用し、固定色を避ける。7ロケールに翻訳を追加する。達成済みフラグはクラウド、ローカルはキャッシュのみ。
