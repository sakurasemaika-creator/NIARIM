## 実行・中断・追加の固定規則

1. `ASTRA_CONTINUATION.md`の`current_id`は本文の先頭未完了IDと常に一致。`todo → in_progress → done`。環境不足/外部依存は`blocked`で、current_idを保持。同じID内の実行可能部分を進める。未確認をdoneやN/Aにしない。
2. 先行IDを飛び越えない。例外はcurrent IDの前提を直接壊す変更、明確な重大security/data-loss/regressionだけ。例外ID・理由・証拠・復帰IDをProgressへ残す。
3. 新発見の実装済みcontrolは割当済IDで漏れを補完し、未知であることを隠さない。lock後に追加された画面/機能は末尾に新IDを追記し追加理由/発見SHAを記録。既存行の番号/順序/定義を黙って変更・再生成しない。
4. 最近のcommit/他session/旧checkpointから完了を移さない。最新HEAD取得後の差分はcurrent IDの前提だけ確認。全面差分は末尾の回帰フェーズまで保留。
5. 1行の実行中はEvidenceに操作別・状態別・必要matrix・実操作・目視・未確認理由/次コマンドを追記。doneには必要証拠と修正後再検証が揃うこと。中断時に未検証subcaseと次手を残す。
6. Route/Progress/Evidenceの同期commitに`[audit-state]`。Policy/guardは今回bootstrapの副作用では変更しない。両repoを安全なfast-forwardで同期し、他者変更を失わない。mirror差異は先に解消してから再開。
