# NIARIM FCM プッシュ通知: 運用・実機確認

作品広場のベルで開く通知履歴と端末のプッシュは、サーバーが記録したイベントを使う。送信に失敗しても、保存済みの履歴や操作結果は残る。投稿した端末では、サーバーからの登録完了応答でもOS通知を表示できる。

| 通知のきっかけ | 受け取る人 | 通知を開いたとき |
| --- | --- | --- |
| 新規フォロー | フォローされた側 | 自分の作品一覧（フォロワー・フォロー数） |
| 新規ブックマーク・リポスト | 作品の作者 | 対象作品の詳細 |
| 通常投稿を正常に登録・公開 | 投稿者 | 自分の作品一覧または公開した作品の詳細 |
| 予約作品をYouTubeで実際に公開、または掲載を正常に切り替え | 投稿者 | 対象作品の詳細 |
| 新しいミッション達成 | 達成した本人 | ミッション一覧 |

Androidの通知とアプリ内履歴には、操作した他ユーザーの名前やIDを出さず、日時を表示する。フォローは同じ相手、ブックマークとリポストは種類ごとに同じ相手と作品の組み合わせを、同じ端末で初めて観測したときだけ表示する。解除して後日やり直しても、端末内の履歴が残る限り再表示しない。履歴は端末内のアプリ専用領域に保存する。照合キーは受け手・種類・操作した人・必要に応じて作品から生成する一方向の値で、歴代の相手IDを保存するDBは作らない。サーバー側の短期抑制は24時間、交流や投稿・公開の通知行は30日で期限切れ。別端末、再インストール、データ消去、旧版でしか受け取っていない操作、端末が一度も観測していない操作には端末内の照合を適用できない。

「設定 → この端末のプッシュ通知」か、作品広場のベルで開く通知一覧の歯車から同じ設定画面に入れる。フォロー・ブックマーク・リポスト・投稿と公開を個別に切り替えられる。スイッチはこの端末のOS通知に適用され、アプリ内の履歴は引き続き読める。全体をオフにすると端末のFCM登録を解除する。Androidの通知許可も必要。予約投稿の受付と、予定時刻以降に実際の公開を確認したことは別々に通知する。

## AWS と Firebase

- AWS 東京リージョンの `niarim-api` が DynamoDB Streams から確定したイベントを処理する。通知履歴を先に保存し、通知行の条件付き更新で同じ配信の重複試行を防ぐ。履歴を記録する段階の一時的なエラーは再試行する。FCM送信を始めた後は結果不明でも再送しない。
- 予約公開LambdaはYouTubeで公開を確認したデータだけを更新する。送信は既存の `niarim-api` の実行ロールで行い、公開LambdaへFirebase権限を追加しない。
- Google CloudのWorkload Identity Federationと送信用サービスアカウントを使う。秘密鍵ファイルは不要。新しい端末登録は最新のアカウントへ結び直し、新しいAPKだけが交流と投稿・公開のデータメッセージを受け取り、端末で照合した後に表示する。旧APKでのミッション通知の配信は維持する。
- `backend` の型検査・テスト・CDK合成とデプロイ差分を確認してから、`dev_branch` の Backend CI のデプロイ手順を使う。稼働中の特典・料金・Google/SNS設定をデプロイで戻さない。テーブル名と実行ロールは既存リソースを維持する。
- デプロイ後は、既存テーブルの `NEW_AND_OLD_IMAGES`、イベントソースの稼働、ワーカー有効フラグ、FCM認証エラーの有無を確認する。設定が揃っていることはGoogle認証や端末への配信成功を意味しない。

## Galaxyでの最終確認

最新の `dev_branch` APKをテスト端末に入れ、通知許可をオンにして受け手と操作側の別テストアカウントを使う。個人情報、FCMトークン、Google認証情報を画面やログへ残さない。

1. 受け手をログイン状態でバックグラウンドへ。別アカウントでフォロー、公開作品のブックマーク、リポストをそれぞれ新規に行い、OS通知・プラザの履歴・タップ先を照合する。解除後の再操作は翌日以降も試す。別の相手または別作品では通知が届き、自己操作・ブロックでは届かないことを確認する。
2. 通常投稿の登録と公開切り替えを試す。予約作品では、予約受付と実際の公開確認が別の日時で届くことを確認する。ミッションでは新規達成一件だけを使って既存のタップ先も再確認する。
3. 2つの入口と戻り先を確認する。種類別にオフにし、対象のOS通知だけが止まってアプリ内の履歴は残ることを確認する。再度オンにした新規イベントと、アプリ終了状態からのタップも確認する。
4. 受信しないときは Android許可・端末登録・履歴作成・AWSからGoogleの認証・FCM受付・OS表示の段階を分け、実際に通った段階だけを記録する。
